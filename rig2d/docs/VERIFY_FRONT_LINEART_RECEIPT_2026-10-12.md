## 3. 问题一（阻塞级）：§2.4 与代码不符，并与 §5.1 自相矛盾

### 3.1 §2.4 的主张

> **修法**：判据改为**「是不是整幅图」**（宽高都 ≥92% 画面才拒绝）+ 下限 8% + 长宽比。
> **尺寸大小本身不再设上限**——紧凑构图是合法输入。

### 3.2 代码实际状态

| 位置 | 是否已改 |
| --- | --- |
| `validate_head_box`（人工 `--head-box` 校验） | ✅ 已改：下限 8% + `>=0.92*w and >=0.92*h` 拒绝 + 长宽比 0.35–2.8 |
| `head_box_check`（自检） | ✅ 已改：与上一致，`why` 已注明「不再是旧的 8%..55% 上限」 |
| **`fit_head_box`（自动定位路径）** | ❌ **未改**，仍用 55% 上限拒绝 |

[inputprofile.py:30](../probe/inputprofile.py) 仍在：

```python
HEAD_MAX_FRACTION = 0.55
```

[inputprofile.py:115](../probe/inputprofile.py) 仍在：

```python
hi_limit = HEAD_MAX_FRACTION * longest
...
if not (lo_limit <= max(width, height) <= hi_limit):
    raise ValueError(f"头部定位失败：得到 {width:.0f}x{height:.0f} 像素，"
                     f"合理范围是 [{lo_limit:.0f}, {hi_limit:.0f}]...")
```

### 3.3 在同一个输入上重跑自动定位（实测）

```
working size (769, 1024)  profile line_art  bg_reliable False
AUTO FAILED: 头部定位失败：得到 714x798 像素，合理范围是 [82, 563]（最长边的 0.08..0.55）
```

`714 > 563`——被这个未改的上限拒掉。

### 3.4 与 §5.1 的矛盾

§5.1 写：

> 自动定位在这类**紧凑人像线稿**上仍不达标（返回 714×798，**超过合理上限**）

「超过合理上限」正指 §2.4 声称已删除的那个上限。**两节不能同时为真。**

### 3.5 一个反向风险：不能直接删掉该上限

若把 55% 上限从自动路径拿掉，`714×798` 会**通过** `validate_head_box`：

| 判据 | 计算 | 结果 |
| --- | --- | --- |
| `inside` | 在 769×1024 内 | ✅ |
| `not_whole` | `714 >= 0.92*769=707.5` 为真，但 `798 >= 0.92*1024=942` **为假** | ✅ 放行 |
| `aspect` | `714/798 = 0.895`，在 0.35–2.8 内 | ✅ |

**即：那个上限既是「误伤紧凑人像」的原因，也是当前唯一拦住该退化结果的闸。**

**必须区分「紧凑但准确」与「退化为整幅图」**——两者在尺寸上都大。可用信号：

- 长宽比（退化常接近整幅图比例）
- 笔画密度分布是否单峰
- 与图像边缘的距离（退化框会贴边）
- 头框面积占比 vs 笔画总面积的比

**不能只靠尺寸上限，也不能只靠 92% 阈值。**
