## 1. 双输入路径的架构后果

这是本方案的核心判断。

**彩图与线稿不是同一类问题，身份由不同东西承载：**

| | 彩图 | 线稿 |
| --- | --- | --- |
| 身份载体 | 颜色、明暗、纹理 | **笔画拓扑**（线的连接关系与走向） |
| ±90° 缺失的本质 | 缺**纹理** | 缺**线画到哪** |
| A 级（对称镜像） | 有效（复制原像素） | 有效（复制原笔画） |
| B 级（块匹配） | 有效（纹理自相似） | **部分失效**：可复制线段，但**不保证笔画拓扑连续**——可能接出断头线或错误分叉 |
| C 级（修复模型） | 有效（照片/插画域） | **需换模型**：通用修复模型在二值笔画域输出的线可能糊断 |

**因此不能只把线稿"当彩图跑一遍"。** 至少三处要分叉：分割、补全、以及**质量判据**（线稿看线是否连续、是否出现断头/毛刺；彩图看颜色与纹理一致性——两者不可共用同一套阈值）。

**同时注意**：`inputprofile.py` 已实现 `color` / `line_art` / `grayscale` 三分类（[inputprofile.py:59](../probe/inputprofile.py#L59)）与两套头框策略（`_fit_head_box_color` / `_fit_head_box_line_art`），所以**检测层已具备分叉能力**，缺的是下游按 profile 分流。

## 2. 线稿路径：一处对我此前建议的更正

我在设计文档 §2.1 否决了「导入图 → 转线条 → 序列模型 → 骨架」。**那条否决对彩图成立，对线稿需部分收回。**

理由：

- 对**彩图**，转线条是信息净损失（丢掉颜色与纹理——那正是彩图的身份载体）。
- 对**线稿**，线条**就是输入本身**，不存在"转"这一步，也就没有损失。此时用**笔画序列表示**是合理且成熟的：`SketchRNN`（Ha & Eck, 2017）正是以 RNN 建模笔画序列（`(Δx, Δy, pen_state)` 三元组流），是该表示法的既有先例。

**所以用户最初的直觉在线稿场景下有真实依据**，我此前的全盘否决过宽。

**但必须同时说清边界**：SketchRNN 类工作产出的是**新笔画的生成**，不做「特定角色的身份保持视角合成」。表示法正确 ≠ 任务已解决：仍须以该角色的笔画拓扑为条件，并保证 ±90° 下拓扑自洽。这条留给阶段 3 的技术选型。

**线稿路径的候选技术（均需核实，不得先写死）：**

| 方向 | 说明 | 状态 |
| --- | --- | --- |
| (a) 笔画图表示 | 矢量化 → 笔画图/样条 → 图或序列模型补全 | 表示法有先例；身份条件化需自研 |
| (b) 线稿专用修复 | 在素描/动漫线稿域训练的修复模型 | **需核实**：域内模型较少，许可需查 |
| (c) 先上色再按彩图处理 | 线稿 → 上色 → 走彩图路径 | 引入上色误差，且上色本身是生成（身份风险） |
| (d) 仅限制线稿的偏转范围 | 线稿只做 ±45°，彩图做 ±90° | 与用户要求不符，须用户确认 |

**建议 (a) 为主**，与方案 §1 的 3D 代理路线可共存（代理给几何，笔画图给拓扑）。**(c) 的风险最高**——把身份交给一次生成。

## 4. 探针改造

### 4.1 取景（先做，其余依赖它）

真实探针 front bbox `[216,0,325,49]` 与合成 `[202,9,511,500]` 差异过大。需要查清并经测试固定：

- 头部在画面中的占比是否应按 `head_box` 归一化到与合成一致的范围。
- 上边缘裁切（`row0 = 0`）是几何定位在下还是**真被裁**——两者修法不同。
- 增加**取景自检**：`silhouette_bbox` 的边长占比、是否触边、宽高比是否与 `head_box` 一致；不满足即拒绝出报告，而非出一份不可比的报告。

### 4.2 按 profile 分流判据

| 判据 | 彩图 | 线稿 |
| --- | --- | --- |
| 补全有效性 | `hole_ratio` + 颜色/纹理一致性 | `hole_ratio` + **笔画连续性与断头率** |
| 失效信号 | 纹理被拉花 | 断头线、错误分叉、笔画被抹平 |
| 同级对比 | 与合成彩图夹具比 | 与合成**线稿**夹具比 |

**现有合成夹具是彩图**（`probe/synthetic.py`，`probe.json` 记 `deliberate_asymmetry: [left_cheek_mole, right_cheek_wisp]`，属彩图特征）。**需新增一个合成线稿夹具**，否则线稿路径没有可信对照物。

### 4.3 双 profile 复跑

1. 合成彩图（已有）→ 重跑，确认取景修复未破坏既有结论。
2. **新增**合成线稿 → 跑通测量管线。
3. **真实彩图** → 走自动头框；自动失败才允许 `--head-box`，且报告中必须保留 `head_box_source`。
4. **真实线稿** → 同上。

### 4.4 回执与文档回流

- `artifacts/run.json` 与 README 更新为实际状态（真实探针已跑、结果如何）。
- 修正 README 上游链接（指向实际位置）。
- 修正 README 测试矩阵的文件归属（`OcPackageShaV2Test` 同文件第二类）。
- `gate` 增加 `input_profile` 字段，使结论可追溯到输入类型——否则同一结论可能出自线稿或彩图，无法分辨。

## 7. 纪律

沿用既有标准，本次特别重申：

1. **不得**用线稿的探针结论支撑彩图路径（反之亦然）——身份载体不同，§1 已列表。
2. **不得**把 `manual(--head-box)` 的报告当作自动管线通过。
3. **不得**在取景未修前比较两个 profile 的 `hole_ratio`。
4. **不得**因契约/测试通过而声明「支持 ±90°」——那是 T6 之后的 gate 结论。
5. `--head-box` 允许作为**诊断**手段，但报告必须保留 `head_box_source`，且不得作为门禁依据。
6. 合成夹具结论一律标 `NOT_MODEL` / `NO_PRODUCT_CLAIM`，不替代真实图。

## 8. 一句话总结

真实探针的 `GATE_PASS_C_VIABLE` 建立在线稿输入 + 人工头框 + 裁切取景三者叠加之上，**不足以支撑启动阶段 1**。下一步不是往前推进度，而是**先让测量可信**（T0–T3），再为线稿补一套对照物与判据（T4–T5），最后用可信数字重出结论（T6）。线稿与彩图的分割方案调研（T7–T8）可立即并行，且是当前最长的前置项。
