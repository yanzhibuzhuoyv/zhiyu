## 2. 新发现：D1 —— 投影与渲染对「头在世界何处」的假设不一致

这是本次诊断的核心，且**同时污染合成与真实两份回执**。

### 2.1 两处代码的坐标系假设

| 函数 | 对世界原点的假设 | 结果 |
| --- | --- | --- |
| `project_source`（P0.3 反投影） | 世界原点 = **图像中心**；椭球固定在原点 | 采样的是**图像中心区域**，不是头部 |
| `render_view`（P0.4 渲染） | 射线窗口中心 = `head_center_world`；椭球固定在原点 | 头出现在屏幕 **`-center`** 位置，而非屏幕中心 |

两者都假设椭球在世界原点，但一个把原点当图像中心、另一个把窗口挪到头的位置——**没有任何一处把椭球真正放到头部**。

### 2.2 实测后果（诊断脚本输出）

```
=== rig-probe-2026-10-12（合成）
  project_source samples cols 192..576 rows 254..770
  head_box occupies    cols 203..565 rows 137..623
  OVERLAP rows: 254..623        ← 头的顶部 137..254 从未被采样

=== rig-probe-real-2026-10-12（真实线稿）
  project_source samples cols 285..426 rows 379..645
  head_box occupies    cols 250..430 rows 40..305
  OVERLAP rows: 379..305        ← 空区间：投影从未采到头
```

**真实探针的投影采样的是躯干/颈部（行 379–645），与头部（行 40–305）零重叠。**

### 2.3 渲染侧的独立验证

真实回执记录 `head_center_world = [-0.0422, +0.9536]`，`pixel_scale = 0.0028129`，分辨率 512：

- 椭球被窗口偏移挤出画面：预测可见行 **0.0 – 49.5**，第 0 行半宽 **54.9 px**（列 215.6–325.4）
- 回执实测 `silhouette_bbox = [216, 0, 325, 49]`（列 216–325，行 0–49）

**逐像素吻合**（列内边界 216 vs 215.6、行上界 49 vs 49.5）。这确认了渲染侧的确切行为：**画面里那条顶部横条，就是被挤出画面上方的椭球的残余可见部分。**

### 2.4 为什么这一条比「取景异常」严重

我上轮把现象描述为「取景异常 / 数值不可比」。实际是**几何根本没套在头上**。后果：

- `hole_ratio` 的分母（`silhouette_pixels`）不是头的可见面积，而是一个被裁切的椭球切片。
- `filled` 的分子（有无纹理）来自**错误的图像区域**。
- 因此 `hole_ratio` **不是**「头部可见部分缺多少纹理」，而是一个无意义的比值。

## 3. 新发现：D2 —— `box_center_world` 调用点轴序互换

```python
def box_center_world(box, image_size, pixel_scale):
    h, w = image_size                      # ← 期望 (height, width)
    ...
    return ((cx - w * 0.5) * pixel_scale, -(cy - h * 0.5) * pixel_scale)
```

调用点（[run_probe.py:206](../probe/run_probe.py)）：

```python
head_center_x, head_center_z = box_center_world(head_box, (w, h), pixel_scale)   # 传的是 (width, height)
```

传 `(w, h)` 而函数按 `(h, w)` 解包 → **`w` 与 `h` 互换**，`cx` 减了图像高度的一半、`cy` 减了宽度的一半。

**这不是 D1 的原因**（D1 中椭球恒在原点，与此无关），但它使 `head_center_world` 本身也是错的，进而让 `render_view` 的窗口偏移也错。修 D1 时必须一并修 D2。

## 4. D3 —— 两份回执互不一致，`real` 并非当前代码产物

诊断脚本对两份回执都按两种约定重算 center：

| 回执 | 记录 center | `(h,w)` 约定重算 | `(w,h)` 约定重算 | 与当前代码一致？ |
| --- | --- | --- | --- | --- |
| synthetic | `[-0.33203, 0.00911]` | `[0.0013, 0.34245]` | **`[-0.33203, 0.00911]`** | **是** |
| real | `[-0.04219, 0.95359]` | **`[-0.04219, 0.95359]`** | `[-0.48242, 0.51336]` | **否** |

另外 `proxy_cover` 字段：synthetic 记录 `1.06`（与其 radii 吻合），real 记录 `None`（但其 radii 恰好等于 `cover=1.00` 的取值）。

**两份回执在两处独立细节上采用了互不相同的约定，而当前磁盘代码只能产生 synthetic 那一种。** 因此 `rig-probe-real-2026-10-12` 不是由当前代码路径产生的（或曾被改写）。

**这一条需要你确认**——你可能知道那次真实探针当时跑的是哪个版本。在弄清之前，该回执的可追溯性不成立。

## 6. 修法（尚未实施）

### 6.1 D1 的真实修法：把几何放到头上，而不是挪窗口

正确语义应是「椭球 = 头，位于 `head_center`」，而非「椭球在原点、靠移动窗口去看它」。

两条等价路线，二选一：

| 方案 | 做法 | 影响面 |
| --- | --- | --- |
| **甲（推荐）** | `project_source` 减 `head_center` 平移；`render_view` **不再**给 origins 加 center（窗口恒朝原点 = 头心） | 改动集中在两个函数的坐标映射；`render_view` 的 `center` 参数可退化为默认 `(0,0)` |
| 乙 | 给 `HeadProxy` 加 `center` 字段，所有射线与世界坐标统一减 center | 定义更清晰，但要动 `geom.py` 的求交与 `symmetry_mirror` 的镜像面 |

**甲更小**，且 `symmetry_mirror` / `hair_shell_mask` 都在代理局部系里工作，不受平移影响。

### 6.2 D2 的修法

二选一，**不要两处都改**（会改回互换）：

- 调用点改为传 `(h, w)`；或
- `box_center_world` 的签名改为显式 `(width, height)` 并改 docstring。

建议**后者**：现有签名 `(image_size)` 解包顺序是隐式约定，正是这次出错的根源；改成显式的 `width`/`height` 两个参数可消除此类错误。

### 6.3 必须新增的自检（防回归）

现有自检**抓不到**这次缺陷，因为缺陷让「几何」与「纹理」同步错位，比值看起来仍合理。需新增：

| 自检 | 判据 | 抓什么 |
| --- | --- | --- |
| `projection_covers_head` | `project_source` 采样区域的 bbox 必须**包含** `head_box`（或重叠率 ≥ 某阈值） | 本次 D1（零重叠） |
| `head_visible_in_frame` | front 视角下 `silhouette_bbox` 必须**不触**画面上/下/左/右边缘（留边距） | 本次「头被挤出画面」 |
| `silhouette_matches_headbox` | front 的 `silhouette_pixels` 与 `head_box` 面积之比落在合理区间 | 分母无意义 |
| `head_center_roundtrip` | `box_center_world` 的结果反解回像素应还原 `head_box` 中心 | D2 轴序互换 |

**`head_visible_in_frame` 一条即可让本次缺陷当场显形**（当前真实回执的 bbox 上界为 0，一触即失败）。

### 6.4 纪律

- 修 D1/D2 时**先写上述自检**（RED，用现有两份回执作为失败样本），再改实现（GREEN）。
- 修完必须**重跑合成 fixture**，并确认新旧 `hole_ratio` 的差异**可解释**（不能接受"数字变了但说不清为什么"）。
- 合成 fixture 本就只有轻微不对称（`deliberate_asymmetry` 两项），修好后 front 空洞率应仍然接近 0——**若修完 front 反而变差，说明修法引入了新错误**。

## 8. 线稿 ±45° 的门禁口径（决策 2 带来的改动）

原门禁按 ±90° 设计（`pass ≤ 0.10`、`conditionally_pass ≤ 0.25`、`side_expected_above 0.40`）。线稿降为 ±45° 后：

- **线稿的判定角度是 ±45°**，`worst_90` 对线稿**不再是判据**（既不通过也不失败，标记为 `not_applicable`）。
- **彩图仍按 ±90° 判**（`worst_45` 定性、`worst_90` 列预期）。
- 因此 gate 需要按 profile 分别输出，**不能共用一份阈值表**——这正是 `NEXT_DUAL_INPUT` §4.2 提出的分流，现被决策 2 进一步加强。
- 角度下调**降低了线稿的难度**（±45° 缺失面积远小于 ±90°），但**不改变 D1 缺陷的性质**：当前 45° 的数字同样不可用。

## 10. 一句话总结

探针存在一处**几何与纹理错位的坐标系缺陷**（投影与世界原点假设不一致），使合成与真实两份回执的 `hole_ratio` 分母和分子**双双无意义**；另有一处调用点轴序互换，以及两份回执互不一致（`real` 非当前代码产物）。因此 `GATE_PASS_C_VIABLE` **两次都不成立**。修法是把椭球平移到头心（而非挪窗口），并先补 4 项自检使其可被当场抓住。**线稿已定 ±45°、彩图 ±90°，需按 profile 分别判定。**
