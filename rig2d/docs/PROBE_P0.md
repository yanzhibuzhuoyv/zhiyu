# P0 探针说明（计划 §1）

探针是计划 §13 认定的「唯一下一步」。它的作用不是展示效果，而是**证伪**一个问题：

> 用一张真实角色图，把正面纹理反投影到头部代理上，在 0/±45/±90 渲染时，
> **每视角缺多大面积的纹理**？这些缺口里，A（对称）+ B（块匹配）能补掉多少？剩下的残差有多大？

若它不通过，后面 7 个阶段的投入全部作废。

---

## 1. 怎么跑

```bash
# 默认：合成夹具（零许可/隐私暴露），约 70 秒
python probe/run_probe.py --out artifacts/rig-probe-2026-10-12 \
    --resolution 512 --grid 128 --texture 768 --supersample 2

# 真实角色图（**不得取自私聊 / 用户媒体库**，计划 §1.1 P0.1）
python probe/run_probe.py --image path/to/character.png --out artifacts/rig-probe-real-<date>
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--image` | 无 → 用合成夹具 | 真实图会被缩放到最长边 ≤ 1024 并转 RGBA |
| `--resolution` | 384 | 目标视角渲染分辨率 |
| `--grid` | 96 | 代理网格分辨率（几何与面积统计） |
| `--texture` | 512 | 纹理网格分辨率（采样）；与代理网格分开，避免把采样间距算成纹理缺失 |
| `--supersample` | 2 | 每源像素发射 2² 条射线 |
| `--dilate` | 2 | 纹理采样间距补齐的迭代次数（**只搬运本图已存在的像素**） |

## 2. 方法（P0.2–P0.5）

| 步 | 动作 | 实现 |
| --- | --- | --- |
| P0.1 | 输入 + SHA | `load_input`；写入 `input.png` 与 `input.sha256` |
| P0.2 | 头部几何估计 → 网格 + 对称平面 | `fit_head_box`（肤色/发色粗筛 + 峰值行宽回退）→ `build_proxy`（参数化椭球，确定性） |
| P0.3 | 正面纹理反投影 | `project_source`：逐采样像素发射线与椭球求交，写入纹理网格；`valid` 取**源图 alpha**，不用启发式 |
| P0.4 | 渲染 0/±45/±90 | `render_view`：相机绕世界 z 轴环绕，正交投影，背面剔除 |
| P0.5 | A → 测量 → B → 测量 | `symmetry_mirror`（A）→ `patch_match_fill`（B，带链式距离限制） |
| P0.6 | 目视对比图册 | `contact-sheet.png`：上排渲染、下排空洞掩码 |

**确定性**：全程无随机数；固定参数时结果逐位可复现（`probe.json.determinism`）。

## 3. 分级补全的定位（计划 §5.2）

| 级 | 手段 | 身份风险 | 本探针的实测覆盖面 |
| --- | --- | --- | --- |
| **A** | 对称镜像（经对称平面 x=0） | **无**（复制本角色原像素） | 极小：合成夹具刻意做成非完全对称（左脸痣、右颊碎发），因此可镜像的缺口本来就少 |
| **B** | 行内块匹配 | **无**（采样本图同行像素） | 窄缝（≤ 12 环 × 4 半宽 = 48 像素的累计距离） |
| **C** | 修复模型（MI-GAN 端侧 / LaMa 桌面兜底） | 低 | **本探针未实现**；残差即交给 C 的量 |

**不得跳级**：A/B 能覆盖的一律不进 C。探针的读数里 `B_patchmatch` 的残差就是 C 的输入量。

## 4. 判定门禁（计划 §1.2，`probe.json.gate`）

| 观测 | 结论 | 动作 |
| --- | --- | --- |
| ±45° A+B 后残留 ≤ 10% | (c) 可行 | 进阶段 1 |
| ±45° A+B 后残留 10–25% | (c) 可行但需 C 兜住 | 进阶段 1，C 权重提高 |
| ±45° A+B 后残留 > 25% | **(c) 单独不足** | **停下重新谈判**（计划 §1.4） |
| ±90° 残留 > 40% | **预期之内** | 侧面/后脑必须生成或由多视角产生，**不视为失败** |

`gate.side_holes_within_expectation` 单独记录 ±90° 是否落在预期区间，
以免把「±90° 缺口大」误读成探针失败。

## 5. 自检（`probe.json.self_checks`）

探针的测量管线本身必须自检，否则它给出的「可行」是假结论。
每一条都对应一个**真实发生过的缺陷**（详见 `artifacts/probe-red-and-fixes-2026-10-12.log`）：

| 自检 | 阈值 | 对应的历史缺陷 |
| --- | --- | --- |
| `front_hole_near_zero` | ≤ 2% | 背面剔除符号写反 → 正面被判成 99.98% 空洞 |
| `side45_worse_than_front` | > front + 5% | 相机环绕方向写反 → ±90° 仍看到正面半球，空洞率算成 ~1% |
| `left_right_symmetry_45` / `_90` | ≤ 2% | 相机或镜像写错 → 左右明显不对称 |
| `texture_valid_fraction_sane` | 2%–95% | 投影没工作（≈0）或把整张图糊上代理（≈1） |
| `camera_basis_consistent` | 布尔 | 固定屏幕平面 → ±90° 仍然是正面半球 |
| `provenance_only_from_image` | 布尔 | B 级输出必须沿来源链回溯到本图（不是只看直接来源） |

**自检全部为 `all_passed: true` 才能引用 `gate` 的结论。**

## 6. 已知边界（必须随结论一起引用）

1. **默认输入是合成夹具**（`SYNTHETIC_FIXTURE`）。计划 §1.1 P0.1 要求最终用**一张真实角色图**复跑；
   在复跑之前，探针结论只能用于「是否继续投入」的内部排序，**不得**写成产品能力。
2. **代理只覆盖脸**（计划 §4.3）：头发是同心壳层、身体不在代理内。
   因此 ±45° 渲染的 bbox 边缘会出现「肘形」色块——那是侧发被当壳层投射的结果，
   属已声明的范围缺口。
3. **`fit_head_box` 是粗筛**，不是语义分割：真实图（复杂背景、深色头发、帽子）可能拟合偏差，
   需要人工看一眼 `proxy.json.head_box_px` 是否落在头上。
4. **C 级未实现**：探针只回答「A+B 之后还剩多少」，不评估修复模型的质量。
5. **`margin` 充足性用的是建模假设**（`1/90` 层宽/度/深度），必须由阶段 3 的**露缝扫描**校准。

## 7. 产物

| 文件 | 内容 |
| --- | --- |
| `input.png` / `input.sha256` | 工作副本与哈希 |
| `proxy.json` | 代理参数：半径、对称平面、网格尺寸、头部包围盒、像素尺度 |

| `contact-sheet.png` | 目视对比图册（上排渲染、下排空洞） |
| `probe.json` | 回执：每阶段空洞残留表、门禁、自检、许可核查、耗时 |
| `NO_PRODUCT_CLAIM.txt` | 显式标注：探针不是产品能力验收 |

---

## 8. 不得宣称（计划 §1.5）

- 不得把探针结果称为产品能力；`NO_PRODUCT_CLAIM` 已随目录写入。
- 不得因一路视角通过而声明 ±90° 可行；门禁只判 ±45° 的残留档位，±90° 单独记录。
- 不得把「残留 ≤ 10%」读成「画质可用」——门禁只回答**面积**，不回答**质量**。
