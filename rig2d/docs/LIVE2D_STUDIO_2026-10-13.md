# 自研动态 2D 角色工坊与实图验证

开发开始于 2026-10-13，最终验证于北京时间 2026-10-14 完成。版本 `0.2.0-studio`。新增可操作的电脑端前视角网格角色工坊，包含导入、标注、局部网格形变、音频口型、保存、下载及重开；Android 接入仍按用户此前“后期接入”的范围留待后续。

## 使用与画面

双击项目根目录 [启动角色工坊.cmd](../启动角色工坊.cmd)，或执行 `.venv/Scripts/python.exe -m studio.launch`。入口 http://127.0.0.1:8808/，监听本机。已有环境可直接使用；未打包 Python 环境到 JAR，也不会自动联网安装依赖。

导入后首先显示中性原始姿态。选择眼口工具并在图片上拖出范围，点击头部中心和颈部支点，保存后启用动画。“头发与附件”支持轮廓、保留画笔、擦除、多个翼/武器图层；可保存下载角色包并继续编辑。详细说明见 [studio/README.md](../studio/README.md)。

## 用户实图，而非仅合成标准图

输入为用户提供的两张附件以及 Downloads/图片.zip 中的 15 张图。包含线稿、浅色肖像、侧脸、手遮脸、复杂彩色背景、真人照片、全身图、截图及武器/飘带。ZIP 7,414,832 字节，解压预算实际 7,997,491 字节，15 个普通文件，路径/压缩方法/CRC/大小经过检查。只在本机使用，所有原件前后 SHA 一致。

最新 [17 图回执 r4](../artifacts/studio-user-images-2026-10-13-r4/summary.json) 使用最终眼口内带与纹理预算实现。17 张都完成工作图导入、资产产生、包导出及重新解析；中性重组与各自工作 RGBA **零差异**。17×256=4,352 个参数端点组合，共 3,012,608 个三角检查均保持正向，最小双面积 0.4621694。总计约 13.87 秒，指电脑 CPU 资产验证，不是手机延迟。

这些检查验证的是原工作图像素、包完整性和网格几何。JPEG 已解码、EXIF 方向已处理，大图会等比缩到最长边 1536；不能把零差异说成 JPEG 原压缩字节或缩放前图片逐像素不变。两张白底附件的原 alpha 都是 255，默认保留整张白纸，不能把它描述为人物已自动抠出。

**自动定位尚未准确**：14/17 使用比例回退，3/17 Haar 检出建议；其中 case04 肉眼可见把背景花纹当脸。两张附件的原默认眼口落到发饰、额发或衣服上。真实浏览器测试使用人工重新定位，明确不是自动地标识别通过。

初次导入及未确认的刷新均保持中性，避免直接把错误位置做成眨眼。用户主动保存、打开已编辑角色包或打开合成示例后才默认启用自然动作。未检出的附件和未确认主体不会自动删除。

## 实际分割测试暴露的不足

使用已有固定 SHA 的 SAM2.1 tiny CPU、2 线程，对两张附件各执行一次编码加 4 组人工点框。没有像素 GT，没有自动类别推断。[实际分割回执 r2](../artifacts/studio-user-sam2-2026-10-13-r2/run.json)。

| 输入 | 模型编码与提示耗时 | 目视与门槛结果 |
| --- | ---: | --- |
| 古风持剑线稿 | 2.647 秒 | 剑和发髻候选相对清楚；剑护手/薄线仍有漏点。飘带候选 0.693，低于原 0.8 门槛，漏段且未采用 |
| 浅色肖像 | 2.504 秒 | 主体候选带背景碎片；脸 0.782、头发 0.651、手 0.792，均被门槛拦截，头发/脸候选明显破碎 |

默认编辑器没有把上述破碎候选直接用于裁人物，保持原图并提供人工修正。未降低原门槛、未声明完整身份或 ±90° 门禁通过。

## 实现与单一数值来源

- `studio/contract.json` 定义格式、角色类别、参数范围与资源预算。Python 是唯一网格增量产生器；vertices/uv/deltas 在序列化前一次规范为 Float32。
- 浏览器 WebGL 按索引绘制原 PNG 纹理；纯 JVM `rig2d.planar` 消费预制增量。两侧将参数规范为 Float32、用 Float64 累加，再一次写回 Float32。没有两套几何生成逻辑。
- 眼口至少 7×7 采样，局部外边界锁定；闭眼内带充分压缩，外侧过渡维持正三角。嘴部是原嘴区域的局部形变，并没有生成看不见的口腔。
- 单个原上传限制 20MiB、解码 40MP、工作最长边 1536；最多 64 层，所有纹理 bounds 合计最多 24,000,000 像素/96,000,000 RGBA 字节。后者只指纹理像素量，不能当整体 RSS。超限整体拒绝，保留上一版，不自动裁翼或缩减附件。
- 包为数据 ZIP，SHA/CRC、有限数、路径、数量和解压预算校验；规范工作图和定义重新派生，严格绑定网格与原图。不同历史开发版 producer 产生的旧草案包可能因派生校验不同被拒绝；这些未发布草案已留历史，未来改 producer 时须显式做格式版本/迁移。
- 存储用版本目录与 CAS 原子指针；磁盘失败后清理未发布孤儿，可重试。并发工作槽保留到实际线程退出，请求取消不会释放仍在运行的重任务。
- GPU 上下文丢失后展示原图；丢失时清除已失效句柄，恢复后新建全部资源。异常网格先校验所有层，再绘制，避免半张角色。

空闲节奏的 JS 与 JVM 调度目前仍各有实现，尚未做逐帧时间轴相同的验收。跨语言一致性结论针对共享预制网格及参数混合，不包含手机纹理上传、空闲节奏或声音播放。

会话再次输入后发现原测试托管进程已退出，因此重验服务并更新启动器为 Windows 隐藏独立进程组/退出父任务组的启动方式，实际重新冷启动和 HTTP health 通过。试用服务仍是易失状态，恢复时须检查，不能把这一次进程在线当跨关机或未来会话保证。

## 当前能力边界与后续

本轮交付的是可编辑、可保存的自研前视角动态 2D 角色工坊。原 v1三源及golden保持逐字节不变，旧多视角 v2/身份门禁未放宽。原角色不可见的侧面、背面、遮挡内容、眼皮和口腔还不能准确自动补全；附件大幅独立摆动仍可能露缝，保守空闲幅度只缓解，不能证明所有姿态都无缝。无 Cubism SDK或 `.moc3` 输出。

用户实图的自动地标/语义部件分割仍未达到发布标准，须继续在真实图上评估。下一步的手机接入需要本地包解析、纹理预算/上传、交互定位、音频 RMS 桥及实际设备性能验证；全双工的真实麦克风、ASR/TTS/AEC和打断验收仍未完成。知语 APK0.2.6/HEAD11b17c7/RAG及原 backend9+23差异完全未改。

研究依据：[Live2D参数机制](https://docs.live2d.com/en/cubism-sdk-manual/parameters/)、[WebGL indexed drawing](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/drawElements)、[OpenCV inpainting](https://docs.opencv.org/4.13.0/df/d3d/tutorial_py_inpainting.html)。实现为自研网格渲染，未使用 Cubism 运行库。依赖 Haar cascade 的原始 Intel/Rainer Lienhart许可保留于 [HAAR_NOTICE.txt](../studio/HAAR_NOTICE.txt)；用户图片只用于本地授权测试，不是可再分发内置素材。
