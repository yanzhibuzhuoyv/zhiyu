# 固定 OC 与每日轨迹图片流水线

2026-10-11，依据用户最新要求。此文是下一阶段实施约束，尚未接进产品；不能将本轮 T2I 背景原型称为已具备参考图编辑或扩图。

## 用户确认的行为

- 本机生图路线在手机完整验收和迁移后替换 Agnes。绘图提示词与图像审核使用用户提供的 API Key；本机推理不消耗生成服务 Key。
- 用户提供的 OC 图片为固定身份依据。后续每天的画面变化来自生活轨迹，人物身份与已确认外形保持一致。
- 原照非全身时默认进入扩图准备；提供明确的“不扩图”选项。这类原照选择不扩图，之后发送的图片遵守已确认取景范围，不能生成、拼接或发送全身照。原照已经是全身时无需扩图，关闭扩图不额外禁止已有全身取景。
- 首次绑定当天即生成轨迹与绘图任务，之后以当地日期零点换日。轨迹、提示词和图片属于同一日期/同一版本；不能把旧图冒充新轨迹图片。
- 出图后二次审核。画面不符合提示词或人物要求时修订并重绘，审核通过再进入当天可发送库存。

## 固定身份与扩图

保存原图不可变字节、SHA、人物确认版本、取景范围及用户的扩图偏好。生成后的扩展图是新候选，不能覆盖原图。扩图通过审核并由用户确认后才成为后续的完整参考；保留原图用于身份对照。

系统规则约束提示词生成和审核，参考图/保护区域约束实际图像引擎。不能仅将“人物保持不变”写进提示词就宣布完成。现有原生研究清单只允许 `text_to_image_background`；它没有通过 OC 编辑/扩图测试，因此不得在产品中默默升级能力标签。需要新增真正的参考图编辑/局部补绘能力，或在用户接受的场景中采用固定主体像素与新背景合成。

主体保护包括脸、发型/颜色、衣饰、标记、身体特征、翅膀数量/位置、角/尾巴、武器与道具。允许遮挡或取景变化，但不可把特征当背景删除或自行增减。未在原图中可见的部位标为未知，不把“没看见”当作不存在；扩图需要补充的外观不得反过来改写已确认身份。

不扩图偏好是输出约束，而非仅隐藏一个按钮。构图提示词、参考/蒙版、审核与发送前检查共同限制最大取景范围。旧库存也必须重新核对偏好版本，不能靠旧的全身图绕过限制。

## 带动作的全身照

人物身份、画面取景和动作分别保存。全身可见不代表正面站姿；坐姿、奔跑、弯腰、抬手、转身、持物或飞行都需要保留动作依据。不能把所有全身参考都归一成站立正面照，也不能因画面中有遮挡就擅自补第二只手或另一只翅膀。

扩图延续原图可见动作、关节朝向、躯干重心、透视、遮挡层次与手/道具接触点，原可见区域受保护。生成新生活动作时可改变姿势，但必须使用参考身份与明确动作约束；固定主体像素合成只能覆盖原姿势可用的场景，不能冒充已经支持任意动作重绘。

动作审核分别检查：肢体与关节连接是否合理、手是否真正握住物体、脚/座椅等支撑是否吻合、武器是否穿体/脱手、翅膀和尾巴的附着位置是否稳定、透视与遮挡是否自洽。姿态关键点/深度等可以提供约束，但通用人形规则不能裁掉非人OC已有的多臂、多翼或其它结构；不引入已取消的2D/3D建模入口。

已确认设计特征是审核依据。透视缩短、侧身、运动模糊、遮挡和合法特殊结构，不因“不像标准人形”自动判为变形；新长出的肢体、错误连接或参考中明确特征的丢失才需要定位。看不清的接触点和不可见部位记录不确定性，不能由审核器先猜再要求生成器照猜测改写身份。

## 统一任务版本

每个轨迹时段的任务保存 `chatId/localDate/timezoneId/trajectoryRevision/sceneId/slotId/notBefore/visualVersion/referenceId/referenceSha/characterPackageSha/framingPolicyVersion`，以及实际生成模型包版本、提示词版本和审核版本。人物档案不存在时明确为空，不能仅凭原图 SHA 推断档案未变。

轨迹先确定活动/时间/地点，再由用户 Key 的语言模型生成结构化图像提示词：场景、姿势/镜头、服饰、人物保护特征、允许取景范围、参考图标识。生成器只取已验证字段；提示词内不得重新发明或覆盖固定身份。轨迹变化时升级 revision，并使旧待生成/待审核任务失效。

日期是库存过期边界，不承诺 Android 后台任务恰在00:00得到执行。换日后的首次前台或后台调度先建立当天轨迹与任务；延迟期间不会发送旧日期图片。生成、审核与发布前均重新核对当前日期及上述版本，过期结果不发布。

当前产品采用 `Asia/Shanghai`，此设计不宣称已经跟随设备时区。实施时将该时区保存到轨迹、任务和库存；后续若允许变更时区，旧快照必须失效重建。允许预生成全天候选，但发送仍检查 `notBefore <= now`；上午不能把尚未发生的晚餐图片当成已经经历的活动发送。

## 以用户 Key 审图与返工

审核器需要实际图像输入。优先使用所选服务商真正支持图片输入的模型；不把 OCR、提示词文本、文件名或生成器自述当作看图审核。无法真实看图时不能自动给通过，也不隐式使用 Agnes Key。

提示词任务沿用已绑定的服务商、模型和人格。辅助视觉审核路由独立配置、验证并授权，不能写回或改变唯一恋人绑定。若当前 Key 没有可用的视觉路由，候选保持待审核，不自动更换恋人模型或公司。现有客户端每条消息最多一图、整次请求图片总量最多5 MiB，同请求可用多条图像消息；参考图与候选图共同送审仍需实际视觉接口测试，不能仅以序列化通过代替验收。

审核请求包含实际候选图、不可变 OC 参考图、轨迹场景、实际提示词及取景偏好，返回内部结构化结论：场景是否一致、人物是否一致、形体/手部是否明显异常、特征/道具是否增减、是否超出取景范围、具体不符点及修订建议。单纯向量相似度或图片 SHA 不能代替这些检查。

审核结果区分 `approved/rejected/uncertain/unavailable`，结构校验合格且为 `approved` 才能入库。审批凭据绑定实际候选 SHA、实际送审参考 SHA、提示词 SHA、人物档案 SHA、轨迹 revision、取景偏好版本、审核模型/配置及任务标识。发送前再次核候选字节，批准 A 图不能用于后来替换的 B 图。图中文字、模型输出和修订建议均不能修改身份档案、任务标识或能力标签。原无人背景审核门禁不用于批准含人物最终图。

默认一次初生成加一次自动修订重绘，二次仍未通过则该候选不发送，不循环消耗用户 Key。用户可以明确发起进一步重试。失败日志保留原候选、实际提示词与各审核结果，不把审核失败改写为通过。第一次生成、修订和审核各自有独立任务标识，重启/重试不重复发起已经完成的收费请求。

本机生成和收费提示词/审核请求分别持久化状态。响应丢失、取消或重启导致收费结果 `unknown` 时不自动重发；只能使用已验证的服务商幂等查询/恢复能力，或由用户明确发起新请求。本地 operationId 不等于服务商保证幂等收费。自动修订次数绑定候选谱系并持久化，重启或换任务 ID 不能重置次数。

审核只决定候选是否可发布；模型不会因审核声称角色身份变化而重设用户原图。审核通过后在现有外观/档案提交锁内执行 CAS，最后检查日期、轨迹、身份、取景偏好与模型版本，才进入 `LocalSceneStock`。

主聊天自然表达，绘图/审核 JSON、技术状态和记忆证据不作为恋人的聊天气泡输出。

## 必须取得的测试证据

1. 真手机完整提示词到 PNG、资源峰值、取消/断连与后台库存恢复；独立 VAE 合成输入成功不能替代完整链验收。
2. 冻结参考图，跨多个动作、场景、镜头、seed反复生成；真人/绘画各自评估。包含动态全身、坐姿、侧身、透视缩短、遮挡、握物、单翼/多翼及特殊肢体，扩图与新动作分别测试。通过率分别记录身份、肢体、翼数、武器/道具、接触/支撑、场景与取景，不用一个综合分掩盖身份失败。
3. 半身/头像扩图保留原可见人物；不扩图分支在生成、库存、发送三处拒绝全身候选。更改偏好使旧候选失效。
4. 首次绑定、零点换日、时区变化、未来时段禁止提前发送、轨迹改动、角色改动、审核期间偏好/档案/候选字节改变、离线/API失败、拒绝后的修订、重启恢复及收费结果 unknown 不重发。辅助审图不能改变绑定；更换任务 ID 不能绕过修订上限。
5. 对审核器做真实图像不一致样本测试，而非只 mock 一个 `approved=true`。用户最终查看实际图片与对应提示词，画质评价样本放 `C:/Users/32202/Desktop/pk`。
