# 独立原文的三层记忆、语义标注与冷归档

每条用户消息和 AI 回复仍分别保存唯一原文、作者、消息 ID、时间和来源。标签只引用原文字符区间，不生成融合记忆、摘要或替代正文。生日、愿望、爱好、承诺是不同类型；反复说想做某件事不能改写成长期爱好。

## 自动识别

Docker 服务默认配置 `ZHIYU_AUTO_MEMORY_ANNOTATIONS=true`、`ZHIYU_MEMORY_ANNOTATION_MODE=semantic`。直接 Python 启动的配置默认不额外调用，启用时选择 semantic；可关闭自动识别或明确使用 literal 兼容规则，语义失败不会自动冒充规则成功。

一轮成功得到聊天回复后，用用户选定的服务商、模型和现有 Key 做一次额外标注调用。两条原话分别传入，识别本人资料、偏好、愿望、习惯及承诺，输出结构化标签；Key 不写入标注库。每侧识别输入最多 16,000 字符，超出的整条保持未识别，不把前段识别当作全文识别。识别有超时预算，失败仍保存本轮原话并显示识别状态。

模型输出必须通过 JSON 结构、类型、作者、原文引用和字符位置校验；日期不能凭服务器日期生成。未说明公历/农历则历法未知；不把 AI 的自述、第三人的生日或引用当用户资料。置信度不足、不确定或无法对应原话时不提升层级。`confidence` 是模型自报分数，校验原文出处不等于证明模型理解正确，层级可手动调整。演示服务没有真实语义模型，明确显示未识别。

普通文本提示加严格响应校验兼容现有公司适配器，没有宣称所有公司都支持强制 JSON Schema。[DeepSeek 官方 JSON 文档](https://api-docs.deepseek.com/guides/json_mode/)另提供强制 JSON 格式能力，仍可能返回空内容。本文实现不依赖该公司专属选项。

现有历史不会在启动时整库重跑模型，避免把万条历史变成未经选择的批量云调用。完整原话仍能检索，历史层级也可手动设置。

## 层级与检索

| 层级 | 行为 |
|---|---|
| 中期 | 临时愿望和普通原话；未完成承诺保留保护标记 |
| 长期 | 同一类型、同一话题跨时间的独立表达增强关注；愿望仍是愿望 |
| 永久 | 本人资料或明确要求长久记住的原话；允许更正 |

自动晋级当前使用可检验的初始策略：至少三次独立证据、跨至少六天；这是待实际使用评估的门槛，不是已证明最优的心理学规律。相同原句复制、同一事件重述不应额外增加证据；不明确时可由用户确认独立表达。未完成或逾期承诺不会因为时间经过被自动算作兑现。

当前相关原文的长期/永久加权为 1.05/1.10，未完成承诺最多另加 0.05，整体上限 1.15；冷原文乘 0.90。标签须与当前返回的匹配原文区间相关才加权，生日标签不能提高同条消息中无关苹果片段的分数。被明确更正的旧标签保留历史出处，停止当前事实加权，并尝试提供其当前修正原文；不能挤掉较新的用户否定。

已更正旧标签沿真实 annotation 链找到当前来源，使用对应原文字符位置；即使当前来源已作为开头候选，也用更正所在的节选替换该角色的片段。不同话题的更正不会共享虚假的旧来源锚点。同条超长原话仍只为每个角色提供一个节选，不能保证所有相距很远的事实同时进入预算。

标注的语义识别与检索索引是两件事：当前原文候选仍使用词项 FTS 与冷 Bloom 目录，不宣称已成为向量库或 DeepSeek Engram。不同说法的标签可归到同一话题；任意同义查询的召回率需要另外验证。

## 冷归档与恢复

安卓保持一个聊天页面，通过“更多→记忆”或消息入口分页管理原话，手动设置中期/长期/永久、恢复自动判定、归档或恢复。操作不编辑或删除原话。

冷归档保留正文，移除该消息的活跃片段与 FTS postings，保存全部原片段词项的 Bloom 目录与来源 SHA。Bloom 只筛候选，命中后仍解码、核对原文并从原字符位置取节选，不能把误阳当真实记忆。恢复重建原索引。启动和直接补索引都会尊重冷状态。

长期、永久和未解决承诺拒绝归档；原先冷却的原话晋级后在同一事务恢复活跃索引。超出冷检索单对预算的原话保留活跃入口。没有自动批量删除或自动生产冷却定时器。

一次冷检索最多扫描 20,000 个目录、读取 32 MiB 目录、解码 64 条原消息，普通解码预算为 256 Ki 字符，首对允许最多 1 Mi 字符。人工归档按双方 UTF-8 大小保守限制，防止活跃伙伴使读取预算失效。达到预算返回 incomplete 和续查游标，不能据此断言用户从未说过。冷回查会与活跃候选同时执行，不因活跃索引已有结果而跳过。

所有管理请求先验证同一身份/会话，修改采用 `expected_revision` 与单个 SQLite 写事务；过期版本返回 409，客户端刷新后由用户重试。原文、标注、冷目录及索引任一步失败都回滚；包括提交错误在内的存储失败返回脱敏 503。

## 接口

```text
GET  /api/conversations/{id}/memory?limit=50&before=<message_id>
GET  /api/conversations/{id}/memory/messages/{message_id}
PUT  /api/conversations/{id}/memory/messages/{message_id}
POST /api/conversations/{id}/memory/search
```

PUT 必须带严格整数 `expected_revision`，至少包含一个操作：`tier=mid|long|permanent|auto`、`index_state=active|cold` 或 `confirm_independent=true`。列表/详情最多显示 768 码点原文节选，包含完整长度和识别模式/状态，完整聊天原文可分页查阅。冷检索返回独立原文 ID、角色、时间、字符区间及完成状态。

SQL 空闲页不一定立刻缩小文件；物理整理需要另建 `VACUUM INTO` 副本并验证后切换，不能把空闲页数当已释放的磁盘字节。正文无损压缩见 [BODY_STORAGE.md](BODY_STORAGE.md)，两万条原文冷归档与新千轮负载证据见 [MEMORY_COLD_PROOF.md](MEMORY_COLD_PROOF.md)，测试与镜像差异见 [VALIDATION.md](VALIDATION.md)。真实付费模型的自然语言分类准确率和权重效果尚未测量。
