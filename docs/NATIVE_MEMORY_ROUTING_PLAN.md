# 手机当下分享与旧事路由：只读研究规划

2026-10-09。本文不改变生产检索，不新增同步云分类请求，尚未实现或启用手机自动 skip。先完成当前完整大库语义检索实测，再决定是否值得接入。

## 已有证据

旧后端 `chat_routes.send → conversation_context_result → memory_lookup` 实际仍查询旧原文。`MemoryAttention` 只是标记上一轮提供过的来源，让模型少重复带出旧事，不能把它说成实际跳过检索。

旧日常路由实验有三轮，不能混成一种成功策略：

| 旧候选 | 重要误跳 | 日常正确跳过 | 结论 |
| --- | --- | --- | --- |
| 最近原型最大相似度 | 首个保留集1/15 | 3/10 | 修表店旧名称被误当当下分享，失败 |
| 最近三个当下原型与旧事原型差值 | 新保留集0/30 | 0/20 | 全部检索，没有优化收益，失败 |
| 固定BGE+监督线性头+分布外否决 | 新保留集0/24 | 5/16 | 只达到研究门禁，未上线 |

第三轮的连续合成200句观察：重要误跳0/120、日常判可跳19/80；分类p95 53.20ms，而当时近期上下文+FTS p95只有7.11ms，因此明确未接入前台。这些是桌面合成实验，不是手机耗时、真人拟人满意度或当前大向量库验证。[旧实验](MEMORY_ROUTE_EVAL.md)、[连续观察](MEMORY_ROUTE_CONTINUOUS_EVAL.md)。

目前手机 `LocalChatRepository.sendMessage` 在 `useRag=true` 时调用 `LocalSemanticService.retrieve`，真正BGE查询编码之后才扫描全库向量。旧 `shouldRetrieve` 关键词门不控制这条路径，日常输入也可能扫描旧库。

## 最小候选接口

复用同一次已经得到的查询向量，在向量库扫描之前调用纯路由策略。不要为判定日常再请求用户模型；不变更恋人性格、当前消息保存、后台标签或文件知识库的独立契约。

```text
完整当前输入 + 正常近期上下文
              ↓
已有端内BGE查询编码
              ↓
查询单独的语义当下分类Q
  uncertain / error / long ──→ 保留完整语义→精确补查
              ↓ 仅Q有充分当下支持
近期上下文C只能否决
  veto / insufficient ──────→ 保留完整语义→精确补查
              ↓
present_only：保留近期原文，跳过较早聊天向量扫描
```

建议纯契约 `LocalRecallIntentDecision(route,reason,modelIdentity,profileSha,rawAffinity,nearestSupport)`。`route` 仅 `retrieve` / `present_candidate`，分数不是概率，不对用户展示内部分类过程。先以 shadow 形式记录决定和纯数值，用真实检索核验后才允许执行 skip。

分类最小资源是随包只读的正/负语义原型，最多128条512维单位向量，附生成模型身份、原型版本、输入SHA和冻结阈值；原型覆盖完整当前分享、隐含旧事、混合需求、承诺、更正、第三人引用、否定和方言/错字。原型只用合成公开输入，不含用户历史或 Key。未知/损坏/维数错误/非有限数/模型身份不一致，一律检索。

最近原型只能作为研究候选。已有首轮错误证明“吃的/出门/现在行动”主题相近不等于不需要旧事实；若原型仍无法过保守门禁，应使用现有训练环境拟合固定512维线性头，手机只运行点积与sigmoid，并由原型最近距离作分布外否决。不新增手机训练库或第二个大模型。

旧冻结线性头不能直接复制：旧表示是无查询前缀的FP32 document编码，手机检索向量是有查询前缀的INT8编码。必须在当前固定手机模型身份、tokenizer、prefix和归一化下重新生成训练表示、校准并冻结；不能直接套旧0.61 affinity/0.50 nearest阈值或当前检索0.56/0.42阈值。后两者解决候选相关度，不解决是否需要旧事实。

## 跳过资格和否决

1. 当前Q必须单独满足强当下支持；近期C不能把不确定Q提升为跳过。
2. 第一版只给完整单查询段资格；多段、巨大UNK、被截断原文、实际字符/模型窗口超限均检索，不把首段代表整句话。
3. C最多四条完整近期原话，保留作者。当前消息在数据库近期列表里已存在，应先排除它，避免重复给Q增加支持。若C需编码且超模型窗口，不截尾，直接否决。C的额外编码只在Q候选时发生，单独计费时延。
4. 指代不明、混合分享与旧事、旧约定完成情况、更正旧事实、与旧个人边界相关的需求均是必须检索类。不能按有没有“记得/上次”硬跳；“还按那个？”和“你当时说能陪到最后”没有普通问法也需要旧事。
5. 个人事实可能让貌似简单日常变得依赖旧信息。标注题库必须带真实合成历史，例如新饮食计划与旧忌口、旧承诺与当前日期；不能只读孤立句子给gold。高相关当下分数不能证明此前没有重要约束。
6. skip只省旧聊天扫描，不能省原文保存/后台识别、取消已保存约定、改固定人格或说“你没有给我讲过”。正常近期原文始终提供，未知旧事仍自然承认没印象。

## 最小TDD与真实验证

- 纯JUnit先红：Q独立、C仅否决、阈值严格边界、同分保留检索、非有限/坏维数/身份错误、完整单段资格、长UNK/多段拒判、无上下文的短指代保留检索。数学替身只验证策略契约，不证明语言质量。
- UUID Android仓库测试：spy确认 `present_candidate` 不调用 `LocalSemanticStore.search/recall`；普通保存、两作者原文、长期标签队列仍发生；拒判真的调用检索，Key不进入路由模块；前台取消和模型缺失可恢复。
- 新独立合成训练/validation/test先冻结，先定一套规则，validation只调阈值，test不可调参。必测旧修表店失败、隐藏历史约束、否定/更正/方言、多句最后才问旧事，先前已见题只作回归。
- 同一实际完整已索引大库A/B：A每次检索，B按新路由。分别记录Q现有编码、新增C编码、纯路由、全库扫描、来源字符数、最终回答等待；同时核对关键原文缺失与错误事实。只以降低全链路等待/旧事打断而未新增重要误跳判断收益。
- 原拟定“重要误跳0、日常至少20%正确跳过”只能作为小样本门禁，有限集0错误不是正确率保证；须报告具体分母和数据来源。p95若更慢或日常全部拒判，应保留候选为研究结果，不能为上线放松门槛。

当前可实现不等于已验证。先量化五千万字已索引库的真实扫描成本；查询编码本已发生，原型dot可能比再编码更便宜，但没有实际手机数据前不宣称毫秒数或整体提速。

## 本轮独立INT8研究结果

已实际完成同手机模型SHA与query-prefix的电脑候选研究：新训练72、新校准48、新保留测试64，已见修表店回归3另计。校准重要误跳0/28、日常跳8/20；冻结后测试重要误跳1/40、日常跳12/24，**未通过0误跳门，未接生产**。错误是看似日常的花生酥分享与隐藏严重过敏旧史。完整方法、分母、失败及纯dot耗时见 [独立研究结果](NATIVE_MEMORY_ROUTING_INT8_RESEARCH.md)。下一步应验证保护性小原文检索与完整覆盖回退，而非利用这轮test放宽门禁。
