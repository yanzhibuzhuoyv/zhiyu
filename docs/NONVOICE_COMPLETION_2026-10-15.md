# 非语音功能收尾与全双工起点

起点 `3733fe6` / 0.2.9。用户要求先完成其他任务，再开始全双工；本报告对应 0.2.10 / versionCode 16 的非语音 checkpoint。全双工进展另记，不混入本版通过结论。旧 APK、回执、RAG 和 legacy 后端改动保持。

## OC 取景、补全与固定参考

“更多→OC 取景与补全”保存原图取景，用户可选保持原样和不补全；明确生成前有费用确认。扩图使用默认 image2.5 参考编辑，提示词与实际双图复核使用用户聊天 Key。未知收费记录和缺失收费账本的孤儿候选均禁止重新自动付费。

候选图保存在私有区，只有当前原图、人物包、取景、服务配置和像素 SHA 均一致，且实际像素复核通过，用户预览后才能确认。已采用图只新增 portrait 参考；原图、原人物包、profile/referenceId/visualVersion 和视频形象均保留。换原图或设置后旧审批不能直接采用。本批使用隔离合成 Key/传输与合成 PNG 验证流程，没有新付费请求；实际画质证据仍为之前八次中转试图，不能把本地通过说成人物一致率。

取景使用独立 revision，完整 SHA 分为两枚库存标签。生活照请求 ID、绑定 proof、提示词、生成/审核、发布、普通聊天配图和主动日常最终提交均检查此取景；旧全身/旧取景图不能在修改后再次发送。风景和表情不会因此全部被禁用。补全原图本身不是日常素材，不能绕过图库入口被发出。

当前每一取景修订仅有一次生成机会；未知或失败不会自动重付费。此版未增加扩图失败的付费重试产品入口，也不承诺全身补全及模型审核绝对准确。

独立审查还确认一项运营边界：扩图私有目录有独立 128 MiB 容量门，现有“候选照片”清理页只管理日常图库，尚不能清理被拒或旧取景的扩图像素。长期多次修改可能耗满扩图预算并暂停新的扩图；此时不会继续扣费。后续清理须保留收费账本和已采用参考，不能直接整目录删除。

## 动态形象草稿与显示资源

未保存草稿采用独立文件和 pending 原子写入，严格绑定聊天、原图、形象身份与父角色包的实际 SHA。保存或明确放弃只清草稿；已发布角色包不受影响。旧角色 namespace 不变，避免升级后视频形象消失。未完成附件允许暂存，最终保存仍要求有效标注。

暂存限 52 MiB（原图最多 20 MiB、JSON 最多 32 MiB），源尺寸不超过 1536。进程内写队列串行编码，修订令牌阻止旧控制器复活已清理草稿，正常重建等待已登记写任务后恢复。150ms 为防抖时间，不是落盘时限；强杀/断电可能丢失尚未完成的编辑，撤销历史也不跨进程保留。真实 Activity 旋转和 OS 杀进程未作为本次实测结论。

本轮实际发现预览采用后硬件 Canvas 使用已回收 Bitmap 的崩溃。修复让渲染持有独立、不可变、有界副本，控制器只回收自己拥有的源图；呈现副本交由视图系统与 GC 释放。编辑器同类问题以两个真实失败断言复现后修复。[Android Bitmap 生命周期说明](https://developer.android.com/reference/android/graphics/Bitmap#recycle())支持此处理，不能只靠绘制前判断或延迟回收解决缓存绘制命令的引用问题。

1536² 原图/60 附件预算构建已在 AVD 实测：3.829 秒，采样 Java 峰值 42,638,592 B、native 峰值 35,256,784 B；超预算分支 0.271 秒提前拒绝。数值是构建阶段分别采样的堆指标，不是总 PSS、VRAM 或红米性能。编辑显示额外不可变源图最多 9 MiB；旧视图命令持有时间由系统管理。
