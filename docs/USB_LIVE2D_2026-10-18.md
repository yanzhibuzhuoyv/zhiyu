## 真实设备发现

本轮只读检查用户授权的当前 OC 原图和 `active.planar`。原图与角色包留在本地 `artifacts/usb-live2d/`，不提交私图或包。当前角色包目录散列与 `chat:原图 SHA-256` 一致，排除“读取旧图角色包”。包通过 fixed-scene-v2 背景保持标记，尺寸 1220×1224。

包仅有 `base`、`eye_left`、`eye_right`、`mouth` 四层，标注 `parts=[]`。这些层的头部、呼吸、摆动参数均为零，因此等到眨眼周期或实际语音输入之外，画面不会出现头部动作。这不是仍在云端生成。

人物活动范围有 11 笔、990 点擦除记录。左眼框约 77 像素宽，实际可动纹理仅 16 像素宽；右眼框约 92 像素宽，可动纹理仅 18 像素宽。活动范围被缩小，进一步降低眨眼可见程度。原图中嘴被麦克风遮挡，现有嘴框落在麦克风上；不能凭空生成可见嘴部，应该关闭口型或由用户重新标注。

## 修复边界

- 给只有眼口动作的包显示准确状态与修正入口，避免把没有头部动作的包笼统呈现为已完成的动态形象。
- 在编辑器添加“补充头部微动”建议入口，根据现有头部、颈部和眼框加入可编辑的局部活动层。用户可以调整、撤销，正式保存前不改变通话包。
- 保留全部原背景、原图、已有锚点、可见性、主体遮罩和笔迹，不自动清除用户修改。
- 局部动作须保持轮廓与背景静止，被头部区域覆盖的眼口继承相同微动场；不把整张图移动或放大冒充人物动作。
- 不声称自动生成了 Cubism 模型或补出了遮挡部分；麦克风、武器等需由用户根据原图决定是否参与动作。

正常 MainActivity 页面实测，原图 Canvas 可正常显示；在同一工坊内从已保存角色包切换到当前标注生成的预览包后，动画区会变白。这是正常 App UI 的问题，与之前 MIUI 拦截测试活动分开记录。

新增 `PlanarDialogDocumentReplacementNativeTest`，在真实 Dialog 的相同 260dp 预览框内红→绿→蓝替换文档，逐次验证至少 6 帧、非零测量、新 Surface，以及 PixelCopy 得到相应 GPU 实际颜色。原实现 AVD 基线 `usb-feedback41-planar-dialog-red-r1.log` 为 1/1 **通过**、1.749 秒，文件名含 red 也不能把它称为 RED；手机正常 UI 的白屏和 0×0 日志才是本故障的实际复现。

兼容修复将文档变化的 key 提升到整个预览布局/interop 所有权范围，原生 Surface 在 `AndroidView.factory` 内创建、`onRelease` 释放，生命周期观察该实际实例；不再在外部 remember 原生 View 后仅替换局部子树。轻量 owner token 避免每次口型更新计算整张 PNG 的 hash。遵循[官方 AndroidView 互操作建议](https://developer.android.com/develop/ui/compose/migrate/interoperability-apis/views-in-compose?hl=en)，未降低 RESUMED 条件、未改 z-order 或放大动画。修复有效性仍以同手机替换后非零尺寸、真实帧和像素对照为准。

## 最终采用：同一 Surface 热换 GPU 文档

`usb-feedback41-live2d-gpu-state-r1.log` 的新 View 连 `surface-created` 都未发生；GLThread 等待在 `GLSurfaceView.guardedRun`。旧 View 已完整完成上传、绘制和第 30 帧。由此采用同一已显示 Surface 的热换方案，避免在这个手机 Dialog 中替换原生 Surface。

- UI 只把不可变文档提交到 Atomic latest-doc；GL 帧边界释放当前 context 中的旧纹理/程序、初始化最新文档的新 generation，再绘制。主线程不做 GL 调用。
- 暂停时不跑帧，待恢复 EGL context 时采用最新文档；失败后可提交新文档恢复；stop/release 清空 pending。视图创建仍在 AndroidView.factory、生命周期仍按 RESUMED。
- `usb-feedback41-planar-hot-reload-red-r1.log`：1/1 真实 RED，准确失败在旧 owner 会创建新 View 的 assertSame 门。
- `usb-feedback41-hot-reload-caption-green-r1.log`：33/33 通过，53.124 秒，包含真实 PixelCopy 红/绿/蓝、同 Surface/新 generation、暂停中提交后恢复、最新提交胜出、失败后恢复、stop 丢弃，以及既有资源预算/工坊/生命周期回归。
- 真机 `usb-feedback41-live2d-hot-reload-phone-r1.log` 的新进程中，同一个工坊 Surface 成功从 generation 1 热换到 2，两个 generation 均有首帧和第 30 帧；`usb-feedback41-live2d-hot-preview-r1.png` 显示当前原 OC。这才是本轮白屏修复的真机依据。

热换成功后另发现留白区透明，透出下方聊天。`usb-feedback41-letterbox-red-r1.log` 1/1 真实 RED（alpha 期望 255、实际 0），1.022 秒。最后最小修复由 PlanarPreview 把 Theme.surface ARGB 传到 Surface，再由 renderer 在 GL clear 时使用预乘颜色；直接 Surface/Renderer 默认仍透明，不改离屏透明契约，也不因主题颜色变化重建 Surface。现有 Dialog PixelCopy 保留中心颜色/热换/暂停门，并增加留白 alpha/RGB 门；此最后视觉修复的 GREEN 和最终整轮由 root 汇总。
