# 视频人物动作与音色分组

最终状态：0.2.12 已打包，`device-feedback-final-native-r10.log` 中本组自动网格 2 项、人物预览 3 项、男女音色 UI 2 项全绿，整轮 348 项通过；823 JVM 全绿。来源、边界及 APK 见 [最终报告](DEVICE_FEEDBACK_2026-10-16.md)。文末 RED 是过程证据，不能用合成检测结果冒称真实复杂 OC 自动识别率。

## 现象与修改

0.2.11 通话仅在用户进入“动态形象”并保存角色包后才有局部动画。仅导入或生成 OC 图片的入口走 `CharacterPreview(..., OcMotion())`，所有动作输入为零，因此图像一直静止；不是云端还在生成。

新增 `CallCharacterPreview`。正式保存的、与当前照片绑定的角色包优先使用。没有包时，读取当前确认原图，最长边缩至 768，再由 Android 随系统的本地 FaceDetector 尝试单正脸定位；仅单脸、置信度至少 0.8、眼距至少 18 个预览像素、偏角在 18 度内且区域完整时，制作临时面部局部网格。过小的脸回到手工标注，避免生成肉眼不可见的动作。临时网格每轴至少 9 个采样点，径向包络的全部受影响三角形都在椭圆脸部轮廓以内，矩形纹理边界和实际脸部轮廓均保持固定；内部用平滑包络呼吸与轻微偏转，实际 idle 采样位移至少半像素的合同单独验证。全部背景网格保持静止，不平移整幅图片。中性状态重新合成与源图像素一致；临时副本不修改原 OC、原图、视觉版本或已保存角色包，不调用生图 API。早期 0.22 缩小现有 basis 的方案因实际位移过小已替换，不拿参数改变当作可见动作。

这种检测仅用于提议局部动作，不是完整 Cubism 建模。它没有可靠的嘴部地标，因此临时模式关闭眼睛和嘴巴表情，不能声称其已有准确口型。多人、侧脸、线稿和未识别图片保留原图，明确提供“标注人物，让 TA 动起来”，直接进入既有手工工坊。无论临时或正式动画，通话都提供“调整人物动作”。用户手工保存的包继续支持已确认眼口、头发、翼、武器等局部动画与口型。

预览绑定完整身份快照；更换原图会取消旧准备，迟到结果不能替换新照片。临时解码像素只在离开后台处理后回收；交给显示列表的副本由 GC 管理，避免旧显示列表触发 recycled bitmap 崩溃。
