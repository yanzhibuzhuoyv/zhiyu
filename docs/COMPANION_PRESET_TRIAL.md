# 温柔相伴：试用预设

电脑入口：<http://127.0.0.1:8798/trial>。选择AI公司，输入自己的API Key即可开始一段持续聊天；名字、称呼、形象和模型可在首次绑定前设置。预设为 `warm_v2`，性格底色温柔、亲昵、细心，有轻微幽默；允许不同意见、犹豫、安静陪伴和暂时妥协。一次收敛或让步不自动变成永久性格变化，也不改动已绑定的设定。

新安卓包：`artifacts/ZhiYu-0.1.1-warm-v2-debug.apk`。在“恋人设定→我们调好的恋人”选择“温柔相伴·试用版”。默认仍为原温柔体贴，老绑定保留原人格；初版 `warm_v1` 继续可读取、不能静默升级。试用版也是固定预设，首次成功绑定后公司、模型和整份设定不可更换；自行调教仍可调整自己的内容。新安卓包内置模拟器后端 `10.0.2.2:8791`，真机需要开发设置中的可访问地址。

电脑页使用独立Docker项目 `zhiyu-companion-trial` / `trial-data`，端口8798。刷新后重新输入原Key，恢复同一段聊天；浏览器只保存公司、模型、设定及会话ID，Key和token不写浏览器存储。另一Key找不到已绑定会话时拒绝另建。退出仅断开连接。浏览器清数据和换设备的绑定限制与Android本机绑定一样，尚未实现跨设备身份管理。

```powershell
docker compose -f compose.trial.yaml up -d --build --wait
```

日常先回应当下，旧事仅在有帮助时自然带出；不每轮追问、不背诵整段引文。原话仍分别保存、后台语义标注，不做记忆融合。本轮没有把额外意图分类器、来源JSON强制输出或多次AI校验加入每次前台请求，也没有替换生产FTS/Bloom检索或实现Engram。

## 首版对照与新的妥协专项

初版 `warm_v1` 与原 `gentle` 用20题、两思考模式做80次官方DeepSeek单次调用。全部200/stop/[DONE]非空，4条用户主动要求的长回答均超过1000汉字。20题有28条独立合成原文；金标不入提示词、作者/时钟/来源相同。独立AI评阅读完整80条，主问题76/80、证据边界66/80，两个条件同时通过62/80。评阅不是人工盲审，也不是稳定正确率。

| 初版实验 | 两条件通过 | 自然度均分/5 | 完整正文等待中位 |
|---|---:|---:|---:|
| gentle 关闭思考 | 16/20 | 3.80 | 1.114秒 |
| gentle 开启思考 | 14/20 | 3.65 | 2.212秒 |
| warm_v1 关闭思考 | 16/20 | 4.05 | 1.052秒 |
| warm_v1 开启思考 | 16/20 | 4.15 | 1.776秒 |

初版仍有“好像你还没跟我具体讲过”、无依据的制作过程细节、长期/当下范围补造。原严格人格题四臂均有提供毒舌演法或实际演出的失败，这个评阅保留，不因后续用户澄清而改分。初版9份冻结源代码及其哈希保存于 `artifacts/companion-preset-live-20261007-r1/frozen-source`，原报告和80条回答不覆盖。

用户随后说明“性格难以更改，只能说暂时妥协”，因此新增 `warm_v2`，将稳定底色与暂时反应明确区分，并要求长回复不靠编造经历展开。新四步连续专项，关闭/开启思考各实际延续四轮，共8条；全部200/stop/[DONE]非空。两模式近期历史由各自真实回答构成，不能当同输入A/B。这个专项不能代替80题的全面复测，也不能证明长历史或永久人格稳定。[预注册协议](COMPANION_TEMPERAMENT_PROTOCOL.md)。

独立AI评阅新版专项：即时需求/稳定底色8/8通过，证据范围6/8；两处失败是开启思考时排除性地猜测用户内心动机，如“不是你真想把她推远”，并非长历史造假。关闭/开启思考自然度均值4.25/3.75，样本各只有四条，不当作模式总体优劣。完整等待中位约1.231/1.965秒。四步任务完成，不等于全部表达可靠。

实验采用393216最大输出预算、无读取截止，等待模型自行结束。实际App仍2048 token、90秒上游等待；试用环境默认关闭DeepSeek思考。v1/v2各另做真实生产请求路径冒烟，分别1次Key验证和3轮聊天，临时数据、不启用后台标注；6条双方原文保存、409拒绝改预设。生日问答来自近期上下文，`memory_refs`为空，不能当长期RAG命中证据。整个本轮共96次官方调用，未用真实私聊或导入原RAG库。

## 验证与限制

最终Windows/Linux后端各767项通过，覆盖95.12%/95.09%；Android75项单元测试及API36首轮8项专项通过，另保留v1的71项及6项原证据。真实Chromium与真实合成HTTP服务12项交互通过：等待锁输入、纯文本防脚本执行、原Key恢复/另一Key拒建、断开保留绑定、已保存但响应丢失时恢复历史、未知网络结果阻止立即重发。一次测试服务启动竞态失败报告单独保留，增加合成provider就绪标记后通过。

Windows/Linux实验工具各628项通过，两新增实验模块整体覆盖82.66%。Ruff对后端与本轮新增/修改Python文件通过；根目录全旧工具扫描另暴露四处既有导入分组警告，未为本轮改动旧冻结实验。独立代码复审开放C/H/M/L为0。后端wheel实际打包并逐字节核对三个试用资源，Docker与wheel都包含HTML/JS/CSS。

测试服务先设置临时目录再导入应用；隔离子进程用不可读的合成SQLite哨兵验证不会打开继承目录或模型。测试fixture仅回环8799，不调用AI；用户试用8798则调用自己所选的真实服务商。页面资源同源CSP、响应不缓存，Key不嵌入网页或报告。

提示词不是强制的语义执行器：模型仍可能误忆、补造、产生能力承诺歧义或人格漂移。网络失败后立即刷新/重连时，原请求可能还在处理；尚未实现服务端幂等协议，不能保证跨连接绝对去重。后端8791保留原数据卷，8798独立；上线镜像和安卓包指纹、测试日志、独立语义/代码审查与全部失败保存在 `artifacts/`，后续以新版本迭代，不改已绑定人格。
