## 方法与复现

先用现有运行镜像执行千轮预检，再执行万轮最终测试：

```powershell
./scripts/Test-LongFieldsEndurance.ps1 -Turns 1000
./scripts/Test-LongFieldsEndurance.ps1 -Turns 10000 -KeepFailedVolume
```

每次使用全新带runID与scope标签的命名卷，以及独立的artifacts输出目录；镜像标签解析为固定SHA256。network=none，仅在容器内启动真实Uvicorn loopback HTTP；UID10001、只读root、只读scripts、1GiB内存上限、128MiB临时目录。聊天库在新磁盘卷，不挂原8791卷。删除前重新核对完整卷名及两项标签，失败保留host报告；卷清理失败也不能判为通过。

`-KeepFailedVolume`仅在进程或核验已有失败时，保留归属核验通过的本次专用卷供诊断，报告和退出码仍失败；成功路径仍移除该卷。不要把保留数据当作清理通过。

所有轮次经实际POST接口发送，每个成功回包的完整正文和元数据生成SHA256。内存仅保留全部签名、长度/耗时及第1/250轮原文，没有保存全历史的第二份全文。每100轮原子写入JSON进度；没有自动重试掩盖失败。总轮数包含探针，不能用循环计数代替消息核对。

千轮和万轮检查点各6项：早期16k用户/AI的中部、尾部，以及第250轮64k AI的中部、尾部。按原ID、role、turn_id、时间、原文子串和截断长度校验；AI探针短回复不回显锚点，避免把答案字符串当来源通过。检查点从最近100条分页至起点，逐条核对内容/来源/metadata哈希、配对、顺序、无重复缺失。

其他检查包括16,001字符输入422且消息/索引/正文计数不变、不同身份读写404、应用实例重建后旧token401及同Key恢复全部历史。实例重建是同进程停止Uvicorn并fresh create_app，不是Docker容器重启。每阶段逐条核对消息全部片段偏移覆盖及对应FTS行，SQLite quick_check必须ok；这不等于验证所有词项或所有语义都能召回。

测量包括主库/WAL/SHM、正文UTF-8字节、角色长度分布、FTS及片段相关页分配、空闲页、HTTP耗时、进程RSS和cgroup内存。RSS包含Uvicorn应用、合成回复器、HTTP客户端和核验脚本，不能与先前纯后端RSS直接比较。只读测量不checkpoint或VACUUM；清理自身会话后核对空库基线，并关闭服务与会话。数据卷最后由driver核验后删除，报告存于独立host目录。

运行期间可用 `Measure-LongFieldsEndurance.ps1` 记录增长。采样前核对容器完整名称、scope/run标签及 `/data` 精确卷名；SQLite以 `mode=ro` 和读事务取得计数、原文字节、索引页的一致快照。文件尺寸、进程与cgroup数据在关闭读事务后紧随采集，属于并发采样，不能声称与SQL快照完全同时。`sample-near-*.json` 的文件名只表示附近轮次，报告中的实际消息数才是基准。
