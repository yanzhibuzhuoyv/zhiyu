# 手机全双工、REA 参考与流式首句

非语音 checkpoint 为 `aa3cc5a` / 0.2.10，710 JVM、241 AVD 已冻结。此后新增前台连续录放、打断及流式回答。旧回执、原图、rig2d 核心、声音模型和桌面旧 APK 保持。本轮无真实 Key、收费调用或手机 USB 操作。

## 可用行为

通话页点“接通”并允许麦克风后，持续监听，不用每句手动提交。ASR 和 TTS 分别持有 native 模型，40ms PCM、有界文本/声音队列、通信路由/焦点和平台 AEC；讲话可以打断旧播放、取消其网络请求。后台、关闭页面、挂断和权限失效均释放；回到前台不自动开麦。原背景人物动画及口型沿用已确认形象。

DeepSeek 通话现在使用官方 SSE：正文第一句可先交给现有分句/TTS 管线，不等服务器尾流完成。其他公司暂保留完整回答后分句朗读。普通键盘/图片聊天保持原路径，不为兼容失败重新发送收费请求。规范来源为 [DeepSeek 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

仅 choice 0 正文可朗读；独立思考字段不输出，内嵌思考标签和工具调用拒绝，图片/日历控制标记跨任意分块也不朗读。总响应 2MiB、单事件 64KiB，严格 UTF-8；必须非空正文、stop 和 DONE 全部满足才正常提交。截断、长度用尽和错误不冒充完整回答。网络使用永久可取消的 OkHttp Call，禁重定向、重试和 POST 重放；连接/写入有超时，完整答案无固定读取总时限。

ASR partial 仅临时字幕，final 才写一条用户原话。完整助手回答走原日历/素材解析和事务门；已经生成但被打断或失败的自然前缀，独立保存为 `origin=call_interrupted`，显示“话说到一半”。这表示生成过，不证明全部播放，也不补写后半句。近期上下文、语义/精确/冷库/更正补链保留这个状态，不能据此认定完整承诺。该状态只加来源元数据，没有改向量、分片或排序，没有原文融合。

每轮 collector 持有取消权；重复/倒序 stamp、迟到网络和口型回调失效。重复挂断共用同一个释放任务，避免旧会话在新通话启动后才恢复系统模式。SQLite writer 等待、编码后和提交前都检查取消；旧 user/已提交完整 assistant 不回滚。未完成前缀及历史刷新使用 2 秒协作式清理预算，不能保证阻塞系统 I/O 在固定时间内退出；失败给出简短保存提示。

## rea-reverse 和 VoiceMem 的取舍

已实际阅读 AiYu 通话实现，并用 smali 交叉核对流式数据到句级 TTS；本轮自主实现这个有用的思路，未复制第三方反编译代码。其无界队列、弱打断判据、通话文本合并和 SharedPreferences 字符串检索不采用。[研究快照与代码证据](REA_SOURCE_REVIEW_2026-10-15.md)记录的是接入前对照；本报告描述接入后状态。

用户说的 134ms 对应 [VoiceMem 原论文](https://arxiv.org/html/2608.26005v1)。本轮复用 5,000 条合成原文和十万真实 BGE 向量测试了派生分区路由：8/64 分区虽快，却只保持平均 81.25% 的非空 top-8；全部分区才完全一致，又更慢，因此放弃这个简化候选。论文实体图和流式预取没有完整移植；不能把实验失败当成否定整篇论文，也不能称手机已经达到 134ms。[同库 A/B 与可复现边界](VOICEMEM_RESEARCH_AND_AB_2026-10-15.md)。原语义优先及精确补漏继续使用，大库原约 20.66–21.56 秒限制仍存在。
