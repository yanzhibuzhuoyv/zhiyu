# 手机全天行为轨迹

本轮补齐用户指出的首次初始化缺口。此前本机已经有全天计划与回复／图片标签接入，但只在第一次准备回复时生成当日记录，尚未在成功进入聊天时初始化。

## 当前实现

- 成功验证 Key 后，为固定唯一聊天立即建立当日轨迹；不等待第一条消息，也不等待次日零点。恢复已有聊天和创建唯一聊天的入口同样执行幂等初始化。
- 同一聊天、同一天只保留一份计划。恢复、重复刷新、换外观不会重新洗掉当天安排；旧日轨迹和全部原话保留。首次验证失败不创建关系或轨迹。
- 以北京时间 `Asia/Shanghai` 的零点作为日期边界，与既有日轨迹规则一致。系统改时区不重标日期，时钟倒退时使用已存对应日的原计划。
- MainActivity 前台生命周期启动零点检查；后台使用 WorkManager 零点尝试和15分钟修复任务。后台休眠／省电／厂商限制可能延迟物理执行，不能保证系统每晚00:00:00唤醒。恢复前台和准备回复按实际当天日期补齐，晚到任务不发布昨天的计划。
- 计划当前时段已经写入正常与主动回复上下文；图库候选沿用时段标签、当天 ID 和 OC 外观版本检查，过期人物图不会按新 OC 自动发送。

## 明确边界

目前是本地四组全天活动模板，按聊天与日期确定计划，并持久保存；没有声称已经上线 LLM 自主规划完整一天。轨迹属于 OC 的虚构设定，与用户真实位置、经历或约定分开。时间未到的活动是安排，不能说已经发生。

Agnes 已通过生图／参考编辑／识图调用测试，但这不代表每日自动产图库存已经完成。当前原生 Agnes 客户端是接入基础，完整的独立凭据设置、两次 OC 生成机会、后台图片任务和真人合成／2D／3D 角色渲染仍需下一阶段接入。不会在 APK 嵌入测试 Key，也不会用 API 成功代替这些功能验证。

## 验证入口

- `LocalDailyBootstrapTest`：首次成功 Key 验证，在任何消息之前写入计划；恢复同一聊天保留原话和当天 SHA；Key 拒绝不创建计划。
- `LocalDailyRepositoryTest`：重启、午夜、旧日回查、外观变更、不同聊天、数据库完整性失败。
- `LocalDailyRulesTest`：北京时间跨日／下一零点、时区改变、时间倒退、无效时段。

最终执行日志和数量见本轮验证记录；源码或测试文件存在不等于用例已经执行。
