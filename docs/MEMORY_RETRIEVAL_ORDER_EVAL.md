# 原文检索顺序 A/B 研究

2026-10-07，新增隔离研究实现。A 为词项先查、语义补漏；B 为语义先查、词项补漏。生产聊天的 FTS、冷归档、分层与原文生命周期未因此切换。

## 预先固定的实验

- 48 道原创合成题，8 类各 6 题；24 题有可支持的用户原文，24 题为未知事实或日常分享。独立作者在看检索分数和模型输出之前定义 ID、目标原话和不能升格为用户事实的来源。每题另加相同 16 轮日常干扰。
- 两版共用全部符合范围的原文碎片，每路最多 16 片段，最终最多 4 对原文 / 6144 字符。来源作者、时间、ID、字符区间完整对应，不融合记忆。
- 词项路为 SQLite FTS5 的词项精确命中 / BM25；使用现有中文双字词 tokenizer 与 memory_terms。它不是全文字面相等。语义路为已缓存的本地 BGE-small-zh-v1.5、512 维 float32；文档不加指令，查询加官方检索指令。
- 长原文按实际 tokenizer 的字符 offset 分窗，每窗验证模型 512-token 上限，全覆盖至尾部；长查询的每窗都搜索完整范围，取片段最大相关度。相似度不证明事实成立。
- 共同补检触发器只看拟提供的 user 原文：至少两个有效查询词项、覆盖率 ≥0.75；并列多事实、长/32 词项封顶、仅问句/假设/否定来源等仍补检。该启发式偏向字面重合，只作节省一次查询的操作规则，不能称为“证据充分”。
- 两路均执行时，同权 RRF（k=60、每路每对取最大贡献、稳定 tie）；额外“两路必查”对照必须产生同样原文。提前停止但漏事实独立列出，不以 gold 决定停止。
- 目标 ID 与完整目标 quote 同时出现才算原文可用；检索到不当来源本身不是模型误答。回复是否杜撰、误归属、把记录缺失当从未发生，另作逐题人工审查。
- 离线两版 / 对照各预热，每题 5 次交替查询、不缓存 query 向量；模型加载、文档缓存、索引构建与热查询分别报告。追加 1000 / 10000 轮合成原文测新索引增长与尾部召回，性能重复查询不称为独立自然对话质量测试。
- 官方 DeepSeek Flash 48 题每版各一次关闭思考，共 96 次；预先选定最长原文、AI 猜测、多事实、未知问句各一题，追加两版打开思考的长回复，共 8 次。AB/BA 交错，固定 UTC、同近期上下文、同人格提示；A 回答从不进入 B 历史。393216 输出 token 上限，read / whole-request 不设截止，须 stop + DONE + 非空全文；完成率不等于准确率。

## 执行

```powershell
uv venv backend/.venv-route
uv pip install --python backend/.venv-route/Scripts/python.exe -r scripts/requirements-memory-retrieval.txt
backend/.venv-route/Scripts/python.exe -m scripts.eval_memory_retrieval_ab --output artifacts/retrieval-order-20261007-r1
backend/.venv-route/Scripts/python.exe -m scripts.observe_memory_retrieval_ab --output artifacts/retrieval-order-live-20261007-r1
```

两个输出目录必须不存在。凭据仅从获授权的 `../rag-system/.env` 读取，校验官方 HTTPS 地址与前后 SHA；报告不含 Key、令牌或思考文本。数据都是独立合成，未读原私人 RAG 数据库。研究依赖不会进入生产镜像。

模型说明见 [BGE 官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)；相关度排序与事实支持是两项任务，参考 [Sentence Transformers 官方 retrieve/rerank 文档](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)。

## 结果与选择

目前没有稳定赢家，保留两版。48 题有 45 题两路都执行，最终提供的原文与提示完全相同；另外 3 题提前停止。检索中位仅差约 0.04 毫秒，不能据一次模型输出或约 0.13 秒的云等待差异判定检索顺序优劣。

| 冻结 R1 指标 | A 词项先查 | B 语义先查 | 两路必查对照 |
|---|---:|---:|---:|
| 24 道已有事实题的必需完整原话可用 | 24/24 | 24/24 | 24/24 |
| 每路必需独立原话总数 | 30/30 | 30/30 | 30/30 |
| 首路就停止 | 3/48 | 3/48 | 0/48 |
| 提前停止后缺必需事实 | 0 | 0 | 不适用 |
| 240 次热查询中位 | 9.279 ms | 9.318 ms | 9.367 ms |
| 热查询 p95 | 10.715 ms | 11.072 ms | 11.163 ms |

独立 agent 逐条阅读 R1 的 104 个完整答案及实际提供的原文，非外部真人评审、未盲化：普通已知事实两版各 24/24；未知事实保持正确范围 A 17/18、B 18/18；日常先回应当下且未硬插旧事各 6/6。A 对假设猫名说“不是你现在这只猫的名字”，属于把未知写成否定；同题两版提示 SHA 完全相同，不能归因顺序。B 也出现将 AI 的“海拔未确认”评语归给用户，额外来源问题独立记录，不藏进主要值指标。

实际普通等待（检索＋组提示＋完整云回复）中位 A 0.941 秒、B 0.808 秒，p95 1.202 / 1.159 秒。首批 8 条打开思考的长回复约 8.02–16.52 秒，但只有 2/8 满足请求的 1200–1800 汉字；全部 stop + DONE 不等于长度遵从或事实正确。模型加载与建索引不计入热查询或云等待。

### 长回复聚焦问题、空正文与复测

R1 为扩展输出把长度/陪聊要求拼入检索 query，两版都从长原文选出旅途前段，尾部的露营地点没有进入模型提示。这是**试验参数混入检索的失败**，不能宣称 R1 长题全通过。

随后只将试验输出设置与原始记忆问题分离：检索用原题，生成提示仍含同样长回复要求；不改模型、题集、门禁、分窗、排名或原文。不意味着已经能从任意实际用户长消息中自动抽取主题。R2 的第一条恢复尾部地点，第二条官方 HTTP200 / stop / DONE 却只有思考、无正文，脚本拒绝记成功并非零退出。R2 原始结果与日志完整保留。

同参数另开 R3，8/8 都有完整正文，露营地点及并列事实的完整原话重新可用，主要已有值正确、未知值未乱填各 4/4。但记忆范围两版仍各 3/4：B 保养题说“要么…出来了你没跟我提过”，A 工具箱说“颜色，你还没告诉过我”。A 还无依据比较交通成本与未知保养费。**交换顺序与仅靠提示词没有解决事实范围错误。** R3 长度 A 2/4、B 3/4，5/8 达标。它是已见场景的复测，不是新增独立题。

本轮官方调用共 **114 次（R1 104＋R2 2＋R3 8）**，113 次有完整正文，1 次空正文。错误样本未删除或覆盖，没有把技术结束合并为一个“准确率”。模型仍会虚构当时翻过记录、随机没保存或必定记住等机制；这与逐句完整保存的实际行为不同，后续需要事实陈述与来源核验，不能用它包装成已实现的拟人遗忘。

历史结果中 `category` 被 SSE helper 的 `reply` 字段覆盖，审阅按同目录冻结题集的 `case_id` 恢复真实类别，原结果不改。最终代码已通过先失败后通过的回归修正该元数据，并保留 `transport_category`；其收尾结构调整不改变原文检索和模型提示。

### 数据增长与索引体积

| 追加合成轮次 | 消息数 | 片段数 | float32 向量正文 | FTS 文件 | 完整原文 JSON / zlib | A/B 查询中位 |
|---|---:|---:|---:|---:|---:|---:|
| 1000 | 2006 | 2016 | 4,128,768 B | 516,096 B | 322,041 / 13,872 B | 9.165 / 9.344 ms |
| 10000 | 20006 | 20016 | 40,992,768 B | 4,775,936 B | 3,157,041 / 125,771 B | 11.900 / 11.904 ms |

两档长字段尾部目标均可用，完整原文无损解压后逐字一致；每档每路 20 次查询只是性能重复。1000 轮建索引约 5.15 秒；10000 轮约 47.93 秒，复用了前一档已编码的文档，不是纯冷启动。BGE 模型本身 95,827,648 字节的权重属于固定成本，向量随片段数增长，成为主要可变空间；未来应研究量化/按活跃层索引，而非合并或删除原话。

增长语料主要是高重复短日常，另带一条 3500+ token 长原文；原文全块 zlib 的高压缩比不代表真实长字段、逐消息生产数据库占用或万轮自然对话质量。本实验没有迁移生产分层、修订、冷归档及向量索引的持久生命周期。

## 验证与证据

最终 Windows / Docker Linux 全脚本各 **396 passed**，新增四模块合计 **88.33%**（454 statements / 53 missed）；Ruff、原文与 span 校验通过。Linux 以固定已有测试镜像、网络关闭、只读源码、单独允许 NumPy `.so` 的 `/deps` 临时挂载运行合同与模拟调用；实际 BGE 与官方 API 实测在 Windows，未称 Linux 完整嵌入模型运行。此前应用后端 757 项和 Android 65/19 项是历史验证，本轮没有重计或修改 APK。

Docker 本轮又因临时 `sailor-ingest.sock` 无法访问启动失败；核对安装路径进程、绝对目录与仅 0B 临时 socket 后保留并重建两个运行目录，引擎和旧 8791 健康检查恢复。备份目录后缀 `zhiyu-recovery-20261007-170721`，未 reset/prune 或动数据卷。这是临时恢复，根因未证实消除。容器首测 NumPy 因 `/tmp` noexec 无法映射动态库，首失败日志保留，改用单独 `/deps` exec 挂载后通过。
