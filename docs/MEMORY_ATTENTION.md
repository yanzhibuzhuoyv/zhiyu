# 旧事与当下：后台记忆第一版

目标是让用户分享日常时先得到回应，在有帮助时自然带出旧事。原文保留、旧事检索、新消息标注与说话时机分开处理；固定恋人预设不随路由变化。

## 当前路径

```text
当下消息 + 最近原文 + 有界旧原文候选
                  ↓
             同一次聊天生成
                  ↓
       完整原文、索引、待办原子保存 → 返回回复
                  ↓
          后台语义标注 → 严格校验 → 独立标签
```

没有额外的前置云调用判断“是不是闲聊”。仍使用近期最多20轮／48,000字符，以及现有FTS、冷目录和最多4旧轮／6,144字符的检索预算。这里尚未实现向量或Engram召回，不能保证任意隐含表达、同义词都能找到。

同一次聊天模型先回应当前分享和情绪，旧记忆是可选背景。只有有助当前回应时才自然提起；不能因为以前吃过、做过某事就劝阻。用户明确回忆、更正或核对约定时，仍按原文证据回答。

## 避免每轮重复带出旧事

每条`memory_refs`增加`presentation_hint=optional_background`和`recently_offered`。后者仅表示该独立消息ID在上一轮成功保存的请求中提供给了模型，不表示AI真的提及，也不证明用户事实变化。提示模型一般不再次主动带出刚提供过的旧事；追问与更正优先于提示。

来源ID、作者、时间、原文、字符区间及更正关系都保留；不删候选、不靠关键词硬关闭记忆、不把命中作偏好证据。缓存仅同owner/会话最多8个ID，最多4,096个scope，成功保存才更新，删除后清除。重启或淘汰时提示退化为空，不影响持久原文与检索。

这提供了呈现控制，尚不能宣称模型已达到稳定的自然对话识别或人类满意度。后续应分开评价相关旧事被自然使用、无关旧事打断、刚聊过的话被复述、重要约定漏掉，以及情绪回应是否贴合当下。

## 后台标注与恢复

启用semantic标注时，回复完成后一次SQLite事务保存双方原文、原文索引、两条`pending`状态和持久任务；待办插入失败整轮回滚，不返回虚假的成功。任务只保存源sequence/ID/时间/SHA、身份scope、provider/model/version及处理状态，没有Key、登录token、正文副本或思考过程。

识别使用用户所选模型，保持原有每侧16,000字符与15秒预算。工作器最多2个独立后台槽；不占聊天8个槽，不在网络调用期间持会话锁或数据库写事务；有前台聊天时不启动新的识别，已开始的调用不会因此反复取消计费。单owner按原文序处理，目录只看任务之前的标签，较新的更正不会先于旧任务应用。

两角色的成功标注、识别状态和任务终态同事务提交，空数组成功也记录幂等标记。落库前再次核验owner/会话、lease、源作者/时间/ID/SHA及版本；删除中的晚结果不会重建会话。数据库或识别失败不损失已返回原文，标记失败且不自动无限重试。

任务状态`pending/running/waiting_auth`在安卓分别显示整理中／重新连接后继续，聊天可继续。未识别的成对原文暂不能冷归档，避免生日或承诺尚未标注就移出活跃入口；原文依然能被近期上下文和本地索引使用。

后端Key和认证仅存在内存，退出/到期停止后续调用。后端重启不会启动扫描或批量云调用，必须重新通过同一身份的有效认证才恢复其队列。一次任务最多两次尝试，允许一次中断后认证恢复；模型/解析失败为终态，重复中断达到上限也终止，完整原文仍保留。新认证不能被旧任务清理掉；释放lease遇瞬时存储失败后，下一有效认证能再次恢复。

安卓既有设备加密Key保存与401重连保持原策略；“后端队列不存Key”不等于整个设备不保存凭证。当前后端身份与调度是单进程，不能宣称跨多个进程 exactly-once，也不能保证网络中断期间云端计费 exactly-once。

## 标注边界与研究方向

`semantic-v2`提示明确区分真实个人自述、第三人、虚构与一次性任务要求。写作长度、格式、故事情节或单次语气要求不应自动变成跨轮个人愿望／偏好；`explicit_keep`仅用于明确长久记住的请求。旧版本标签原样保留，不自动重跑历史。[五组真实短对话冒烟](MEMORY_ATTENTION_EVAL.md)已运行，虚构写作要求没有生成偏好标签；这是小样本观察，原文出处正确不代表广泛语义准确。

该版本不融合记忆，不生成替代原文的摘要；长期／永久与更正策略保持。后台工作减少了聊天等待的依赖，但并没有省掉识别token，待办元数据也会占空间。原文存储优化仍见[BODY_STORAGE.md](BODY_STORAGE.md)和[MEMORY_COLD_PROOF.md](MEMORY_COLD_PROOF.md)。未来再评价轻量语义路由、待办元数据整理和自然长期对话权重，不在没有数据时随机忘记重要事实。

后台写记忆的延迟与更新时机取舍参考[LangGraph官方说明](https://docs.langchain.com/oss/python/concepts/memory#in-the-background)，这里只借鉴结构，没有引入其框架或融合画像。本轮不是ReAct工具循环或全双工语音开发。

验证及实际服务状态以[VALIDATION.md](VALIDATION.md)为准；新后台短对话等待单独记录于[第一版实测](MEMORY_ATTENTION_EVAL.md)。较早180次思考／长输出测试仍独立记录在[DeepSeek实测报告](DEEPSEEK_FLASH_EVAL.md)，不能把串行旧路径数据冒称新后台延迟。
