# 千轮与万轮连续聊天实测

本轮按用户要求把原来的60轮烟测扩展为1000和10000完整聊天轮。一个轮次包含一条用户消息和一条成功保存的AI回复；测试通过真实Docker HTTP接口，不用批量插入SQLite代替聊天请求。仅使用隔离测试后端显式开启的demo，真实云厂商调用数为0。

## 数据和核对方法

- 总轮数包含检查问题，1000轮时应有2000条消息，10000轮时应有20000条消息。由返回的实际消息签名和分页读取核对，不把循环次数当作保存成功。
- 使用固定seed生成每轮不同的中文手账内容，加入较长消息和超过256轮的相关泛讨论，检查原始早期事实是否仍可召回。检查保留原消息ID、用户角色与时间，区分原文召回和演示回复。
- 两个阶段各8项探针，均计入总轮数：早期纪念日、礼物、昵称、修正、首约会地点、长原文中部、尾部及两条独立原文联合召回。联合例子同时核对原生日和原食物消息，缺任意一条、伪造来源或引用第三方生日都判失败；这些只是合成夹具，不是业务专用规则或真实用户事实。
- 每个检查点从100条最近消息开始，向前读到会话起点；每条核对ID、角色、时间、内容及来源签名，验证无重复、缺失、改写或乱序。另检查同Key重新登录、跨身份404。
- 记录实际请求数、错误、阶段耗时、吞吐及HTTP耗时p50/p95/p99/max。未自动重试掩盖失败；任何探针失败也不能标为passed。
- 只删除本轮UUID演示身份创建的会话并撤销会话令牌，不清除整个测试卷、不读取旧RAG、Key或token不写入报告。

## 复现

先执行项目根目录`./scripts/Test-Docker.ps1`完成构建与基础回归，再执行：

```powershell
./scripts/Measure-DockerStorage.ps1 -OutputPath artifacts/storage-stress-baseline.json
./backend/.venv/Scripts/python.exe -u scripts/stress_companion.py --turns 10000 --report artifacts/companion-stress-10000.json --progress-every 100 --checkpoint-pause-seconds 10
```

第二个终端在1000和10000轮检查点暂停期间分别运行只读测量：

```powershell
./scripts/Measure-DockerStorage.ps1 -OutputPath artifacts/storage-stress-1000.json
./scripts/Measure-DockerStorage.ps1 -OutputPath artifacts/storage-stress-10000.json
```

结束并清理自身夹具后再测`artifacts/storage-stress-cleaned.json`。测量包括主库、WAL、SHM、SQLite页数和空闲页、消息数与正文UTF-8字节数、quick_check、容器内存和后端进程RSS。使用只读连接，不执行checkpoint、VACUUM或删除。容器内存含文件缓存，不能把它的增长直接当作进程内存泄漏；测试清理后主库文件也可能仍占空间，空闲页可用于后续写入。

删除后文件大小保留、空闲页可复用，未自动VACUUM。万轮时容器memory.current=144,101,376B，其中file缓存52,916,224B，不能把容器总量当进程RSS或内存泄漏。仅这些采样不能证明数月运行稳定性。

冻结源码与镜像摘要见`artifacts/stress-final-code-hashes.json`；运行后再次核对一致，镜像为`sha256:26c01106dfd0a8d910a7486e9cf50ea633257a7d9975ed7230d7447ccd4925f9`。主机i7-14650HX、16核24线程、16,869,285,888B物理内存，是共享主机单会话串行测试。Windows/LinuxDocker271项基础回归、94.60%，30harness回归及ruff全过。

旧SQL第一轮在千轮通过后因EXPLAIN发现重复JOIN风险被主动停止，报告为`stopped_after_1000_checkpoint_for_query_fix`；实际停止时2196条测试消息，只清理该随机身份夹具，保留`companion-stress-before-query-fix.json/.log`与相关storage证据。它不是万轮成功。之后仅FTS索引版单独千轮通过（7探针），证据为`companion-index-1000.json`，也不混为当前加权版万轮。

千轮主库暂未变大是复用了原有空闲页，不能宣称保存消息不占空间。当前权重仍是词法启发，附近事件保持未确认原文，不代表真实AI已经理解事实间的联系；默认16场景/24期望命中的权重方案与另一方案同分，不能称全局最优。见`scripts/memory-weight-evaluation.json`。

针对长字段另补真实HTTP冒烟：36条用户16k，AI32条16k＋4条64k，双作者中尾召回、134条原文分页/重启哈希、超限422无写及全部片段覆盖通过。临时空库增至8.87MiB，其中索引4.68MiB；这是独立合成存储边界，不能与本万轮负载混用，见[双方长字段实测](LONG_FIELDS_TEST.md)。

本次是单一持续会话串行测试，适合验证长历史的完整性、召回及增长曲线。它不代表多用户并发容量、安卓端一万条同时加载、真实厂商延迟/费用/回复长度、所有语义回忆质量或长期运行数月的稳定性。
