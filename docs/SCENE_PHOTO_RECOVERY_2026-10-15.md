# 0.2.9 · 候选照片与生成恢复

0.2.8 的生活照队列可能被一张结果未知、无法审图或已失效的旧候选挡住。0.2.9 会保留该次生成记录，跳过这一时段，继续准备后面的照片；每次后台工作仍最多调用一次新生图。新收到的授权错误或余额不足会停止本批，避免连续调用。

## 手机上如何使用

覆盖安装桌面 `知语-0.2.9-手机独立版.apk`，进入原聊天，在“更多→候选照片”查看。列表每页最多 30 条，只在点击“看照片”时解码一张不超过 512 像素的预览，不会打开列表就载入全部图片。关闭、换页、切换聊天或退出时释放预览。

| 操作 | 行为和边界 |
| --- | --- |
| 重新审图 | 用当前聊天 Key 审查已保存的原参考和候选实际像素，可能产生聊天模型费用，不重新生图。当前审核证明已经有效时直接恢复发布，不重复审图。 |
| 重新生成 | 只给明确失败的原请求提供一次机会，弹窗说明生图费用并要求用户确认。结果未知、正在处理、已经重试的请求不提供该入口。 |
| 清理候选 | 确认后只删该候选的私有临时像素及其备份；保留生成记录和标注、恋人原图、已发布或发送的图片，随后唤醒库存准备。 |

照片服务仍需在“更多→照片生成服务”配置独立图像 Key，聊天 Key 用于生成描述和视觉复核。本批没有读取用户提供的真实 Key、调用付费服务或向真实手机安装；0.2.8 的真实 image 2.5 试图记录仍见[上一版报告](OC_BACKGROUND_IMAGE_SERVICE_2026-10-14.md)，没有重标为本批新测试。

## 防止重复收费与旧图误发

- 原请求 ID 不随 Key 或模型更改重抽。明确失败后的重试使用绑定父请求的固定子 ID；重试登记与任务预留在同一 SQLite 事务内完成。重点击、并发登记、重启、子请求本身失败都不能再产生第二个子请求。网络结果未知时保留未知记录，绝不以重置原任务的方式重新收费。
- 原生成绑定、原图 SHA、候选 SHA、轨迹和人物版本不改写。更换 Key 后主动重新审图只增加当前审核证明；任何身份、轨迹、原参考或像素变化都会使旧证明不能发布。发布前再次核对当前资料、联系状态、任务来源和候选清理状态。
- 清理先原子写入已清理标记，再删除本候选文件；即使删除中断，也不能从备份复活。清理与最终发布互斥，网络与解码不放进这些短锁中。
- 损坏的旧像素或标注只影响自己的时段，不删除原记录、不重新付费；后续时段仍可准备。候选库保留 128 MiB / 2048 文件预算，新任务预留前检查容量，满时不消耗重试机会或调用生成服务。检查只是当时的空间快照，系统剩余空间随后被其他程序占用仍可能导致保存失败；写入时继续校验预算。
- 图片、路径、归属和 JSON 都有边界校验；每次只读取当前聊天的分页任务。错误提示不直接显示 Key、提示词或服务端异常正文。

## 迁移和原功能

仅将独立照片生成账本从 v1 升至 v2，新增重试关系表及分页索引，不重建原任务表；真实 Android SQLite 测试验证旧任务保持。`SQLiteOpenHelper.onUpgrade` 迁移和 `AtomicFile` 的存取继续复用平台实现：[SQLiteOpenHelper](https://developer.android.com/reference/android/database/sqlite/SQLiteOpenHelper)、[AtomicFile](https://developer.android.com/reference/android/util/AtomicFile)。

原文 RAG、三层标注、语义检索和排序本批未改，仍不做记忆融合。固定人格、保留上传背景的人物局部动画、原图及用户手动修正继续保留；rig2d 核心 JAR 和契约、193 项资产与 7 个 ARM64 原生库以发布审计核对。旧 0.2.8 APK 和离线学生模型包保留，默认远程照片不需要安装学生大包。

## 仍有的边界

- 自动审图仍可能误判人物细节；这次验证是模拟传输、合成 Key 和隔离 AVD 的正确性检查，不是新一轮真实人物保持率或红米性能测试。
- 为避免无限付费，一次人工重试用完不能再次创建子请求；旧结果未知且没有完整像素的任务不会被重新提交。
- 原生成标注与收费记录会继续增长。清理图片不删除这些记录，达到文件数预算也会暂停新候选；本批没有引入自动删账本或无限库存保证。
- Android 后台和省电策略仍可能延后调度，不保证每天精确发满次数。生活照必须通过现有审核与当前轨迹校验，缺图时不发占位图。
- 自动全身扩图、完整自动 Cubism、用户真机/OEM 验收和真实全双工尚未完成；全双工按要求仍放最后。既有万轮、五千万 Unicode 和学生采样长测未重跑。
