## 时间

原来仍让模型从长上下文中回答时钟问题，提示词不足以保证不回避或沿用旧时间。现在独立的“现在几点/今天几号/星期几”等问题由本机读取当前时刻直接回答，原样保存问答，不经过模型猜测；复合问题仍交给模型并提供本次可信时间和时段，不把其他问题吞掉。

Android 13+ 优先读取系统已有的网络校时时钟，未获得网络时间时使用设备当前时钟；没有另向 IP 定位商发送请求。时区使用手机设置，明确询问已支持城市时使用对应时区；IP/代理出口不作为用户时区。使用方式依据 [Android SystemClock 官方接口](https://developer.android.com/reference/android/os/SystemClock#currentNetworkTimeClock())，不是独立运营一个授时服务。

真机实际保存并返回“现在是12:56:46。”；同次系统快照为 2026-10-18 12:56:46 +08:00。此测试把任何模型请求设为失败，证明该问题真的在本机完成，而不只检查提示词字符串。证据 `usb-feedback41-real-clock-green-r1.log`，1/1 通过。

## 连续输入

- 原来的 1.8 秒静默窗无法知道用户还在写下一句。现在输入框中确实在编辑补充内容时保留当前文字组，最长从本次续写开始等待 15 秒；每次按键不会重置绝对期限。草稿不作为已发送内容提供给模型。
- 回复尚未返回时发来的后续文字可继续排队。中间生成的回复暂存，待该组用户原话全部提交后，再展示恋人的回复段落，避免插入两段用户原话之间。
- 已开始的 HTTP 不取消、不重投；请求开始前的邻近文字仍一次统一生成。请求开始后的新文字可以产生后续请求，页面把回复段落连续展示，不伪称只调用过一次。
- 每个显示组最多 32 条用户原话；达到上限后开始下一组。图片和语音保持原来各自的提交边界。
- 独立的 ID 显示收据保存组内顺序；原始消息、时间戳、内容和 RAG 顺序不修改、不融合。缺少完整组的历史分页保持原顺序，不跨页搬消息。
- 成员归属按有界 ID 查询验证，不依赖最新历史页的 100 条/2 MiB 限制。新增长字段 Native 覆盖超过 2 MiB 后仍能保存收据且不改变原始页。
- 页面刷新在回复暂存期间不会提前暴露中间答复。收据存储失败会保留原文并给出提示，不把回答重新发给模型付费。

当前照片能力快照区分形象、生成与审核条件。条件具备时，不应把“暂时没挑好/生成失败”说成永久没有发图能力；只有真实附图才可以说已发出。图片仍需实际生成、像素审核和发布成功；不能只因为 Key 存在就假装发送。
