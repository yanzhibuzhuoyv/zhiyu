# 记忆权重与保守清理（0.2.19）

> 历史记录：0.2.20 已修复部分向量相似造成的整条原文误删，改为完整原文精确判重，并持久推进扫描位置；本页的 0.2.19 删除策略不再代表当前行为。见 [修复报告](REVIEW_FIXES_2026-10-21.md)。

## 已有权重

本地语义召回不是单纯按余弦排序：候选命中后先乘 `native_memory_annotations` 的层级/置顶因子（长期 +5%、永久 +10%、置顶再 +5%，上限 1.15），再由 `rankingScore = score × relevanceFactor` 排序；词法补漏对用户原话乘 1.3，长期/永久层级乘 1.4/2.0。顺序仍是先语义、后词法补漏。

## 新增策略

0.2.19 增加**旧记忆保守清理**，只在语义索引完成后的后台窗口运行，每个对话每 24 小时最多一次：

1. 只考虑 30 天以前、层级为 `mid`、未手动指定、未置顶、无附件、未被主动联系引用的消息；最近 100 条永不参与。
2. 对每条旧消息取已有语义向量，在同一对话内检索**更新且同角色**的来源；余弦必须 ≥ 0.95，且新来源的层级/置顶权重不低于旧消息。
3. 仅保留置信度最高的候选，删除数量上限为 `floor(旧候选总数 × 2.5%)`。例如 150 条旧候选最多删 3 条；不足 40 条时上限为 0。
4. 删除在单个 SQLite 事务中同时清理 `messages`、`semantic_vectors`、`semantic_jobs`、`native_memory_jobs`、`native_memory_annotations`、注释链接、`memory_fts`、`memory_cold_fts`；附件、置顶、主动来源或并发修订变化会使该条跳过。
5. 删除是永久删除原话，不是只隐藏索引；这是产品明确选择。没有云端上传或额外 API 调用。

## 验证

- 纯策略测试：95% 门槛、2.5% 上限、置顶/附件/引用/长期/永久保护。
- Native：150 条旧候选 + 100 条近期消息，服务按余弦 1.0 只删 3 条；原话、向量、FTS 同步删除，事务后计数 247。
- 万轮：`LocalMemoryEnduranceTest` 10,000 轮 / 20,000 消息，原文 183,882,659 UTF-8 字节，重启全量哈希通过，召回 16.62 ms，耗时 144.8 s，Provider 0。
- 五千万（部分收口）：5,000 条 / 50,000,000 字符写入与重启校验通过；语义索引 4,508/5,000 条、90,184/100,000 分块（90.2%）。前 3 个锚点查询均通过“独立原文召回”，但路线是 `lexical_fallback`、原因 `index_pending`；第 4 个“喜欢哪种花”锚点 4998 未索引，未跑。本轮无官方/付费调用，不能称为完整 50M 语义检索通过。
- 完整 Native：99 类 / 497 项全部通过（`artifacts/memory-prune-final-native-r2.log`），覆盖清理规则、数据库删除、相机、通话、Planar 等既有链路。

## 边界

- 95% 是语义余弦阈值，不是模型自报概率；不同 embedding 模型的分数不可直接互换。
- 只清理已有向量的旧消息；没有向量、模型不可用或历史不足 30 天时不会删除。
- 旧候选超过 400 条时单轮只扫描最早的 400 条，因此 2.5% 是上限而不是保证每次删满。
- 这是保守的去重清理，不是摘要/融合；被删原话不可恢复。
- 50M 只完成 90.2% 语义索引，3/3 查询走词法补漏，不是语义路线；完整 100k 分块与 4/4 查询仍需补跑。
