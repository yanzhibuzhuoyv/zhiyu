# 手机查询表示的日常语义路由：独立桌面研究

2026-10-09。**候选未通过门禁，未接入 Android 生产路径。** 这轮在电脑用手机同一公开 INT8 模型、查询前缀与512维归一化表示实际推理，不是手机耗时或完整聊天 A/B。没有读取私人聊天、数据库或 API Key，没有联网请求模型服务。

## 结论与失败边界

先固定新合成 train/calibration/test，再只用 calibration 选阈值，选定头与原型写入冻结文件之后运行 test。保留集64条：重要旧事误跳 **1/40**，日常正确跳过 **12/24（50%）**。门禁要求重要误跳0、日常至少20%，因此失败。没有利用已见 test 调高阈值或更改金标。

唯一重要误跳是 `test-058`：

> 刚打开一盒花生酥，看起来很好吃。

合成更早原文是“我花生严重过敏，一口就肿。”这条隐藏历史仅作金标说明，不提供给分类器。冻结策略把当前句判为当下分享，affinity 0.618165、最近训练原型余弦0.553791，超过校准门。其后完整检索应当有机会找出过敏原文；跳过可能遗漏关键关心。

这说明“当前句像日常”不能证明旧原文无关。同一句话在有/无过敏历史的两个世界中，当前向量完全相同；仅依赖当前语义及最近四句话的决策无法分辨。改变输出口吻或添加“不要说查记录”的提示词，不会补上没有检索到的旧事实。有限题集0误跳也不能证明这种边界消失。

复用既有 `memory_route_linear_training.py` 的固定balanced L2 LogisticRegression，C=1、lbfgs、random_state=0，不试新的模型/超参数。只用72条训练Q建立72个支持原型和512维固定线性头。校准扫描450组 nearest/affinity 阈值，只允许重要误跳0，在此约束下最大化日常跳过，然后选更严格门。选定 **nearest≥0.50、affinity严格>0.58**。affinity/余弦均不称为事实概率。

Q独立满足才有跳过资格；至多四条完整近期原话C只能否决，不能把不确定Q提升为当下。本研究沿用旧评测器的Q/C均编码方式，包含C的完整时延；“只在Q候选后编码C”的手机调度尚未实现或验证。超512（包含前缀和特殊token）、超8192 UTF-16单窗口、超过100连续ASCII字的巨大UNK、坏输入、坏向量及模型身份不符均拒判并保留检索，不截断末句。

## 实际结果及耗时

| 观察 | 重要误跳 | 日常正确跳过 | 判定 |
| --- | ---: | ---: | --- |
| 校准（选择阈值的数据） | 0/28 | 8/20（40%） | 只属校准表现 |
| 一次新保留测试 | 1/40 | 12/24（50%） | **失败，禁止作为上线依据** |
| 已见修表店回归 | 0/3 | 无日常题 | 已见回归通过，不能加到保留集 |

重要错题全在8条隐藏历史题中（1/8）；其他32条重要题本轮0误跳。显式旧事、混合、承诺、更正、否定、第三人真实旧事、方言旧事均保留检索。五个当下分享因子集被跳过，而亲昵2条/当下安慰1条/近期可解指代2条本轮仍全保留检索。这说明总体50%也不能外推为所有日常类型都受益。

环境为Windows 11、Intel64 Family 6 Model183 Stepping1、Python3.13.5、ONNX Runtime1.30.0 CPU、NumPy2.5.3、scikit-learn1.9.1、Transformers5.10.2，ONNX intra/inter线程均2。保留集完整路由（Q/C推理与scalar参考评分）p50 **5.955ms**、p95 **12.443ms**，上下文否决子集p95 **14.073ms**。这些不是已支付Q编码之后的增量成本。

单独给69个已编码的测试Q/C表示预热3遍、测20遍，共每路径1380次评分：

| 纯评分路径 | p50 | p95 | 最大值 |
| --- | ---: | ---: | ---: |
| Python scalar参考点积+sigmoid | 1.793ms | 2.042ms | 3.606ms |
| NumPy vectorized同一冻结参数 | 0.0484ms | 0.1260ms | 0.4429ms |

两种实现所有评分最大差4.44e-16。72×512 float32原型147,456字节，头+偏置2,052字节。这些是未编码成本之外的桌面评分耗时；NumPy不是Android部署依赖，也没有测Kotlin点积。未测手机共享CPU争用、额外C编码、五千万字向量扫描、最终模型回答或省下的端到端时间，因而不能据此声称手机已经提速。

## 下一轮可测方案，尚未实施

不建议把这次失败改成“只避开食物”的关键词硬规则；隐藏出行、时间承诺或重要旧物也有同一不可辨识问题。保留当前手机全检索默认。

更可评测的结构是**保护性小检索→日常语义分类→必要时全库检索**。先从当前有效、需保护的独立原文指针构成小索引（永久信息/手动pin/待履行承诺/当前更正），每句用同一查询向量查这个小集合；高相关保护原文命中时提供原文且不允许整轮skip。只有完整原文索引/识别覆盖已确认、保护集合未超过资源上限、来源SHA/owner/chat/作者/时间/更正链完整，且Q满足日常门、C不否决，才研究省去全库扫描。后台识别积压、指针不全、未识别关键事实、损坏、模型身份变动、超限一律回全检索。

保护小索引仍是检索，不是记忆融合或摘要：独立原话保留ID、时间、作者、完整SHA与spanSHA；正文保持完整原文，标签只是指针。分类决定只影响取旧事的成本，不影响逐句保存、固定性格或记忆层级，不给用户展示查库过程。

这也不能在尚未标注或小检索漏召回时保证安全。下一轮需要先冻结全新的calibration/test，加入更多无显式旧事词的禁忌、取消/修订承诺与未识别事实，保留本轮花生误跳作已见回归另计。先验证保护机制实际调用和失败回退，再与手机真实完整已索引大库做A/B，分别量Q、C、小扫描、全扫描和回答等待。不能用本轮test重新选门再称独立通过。
