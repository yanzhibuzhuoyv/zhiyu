# OC 外观的三条制作路线

2026-10-10 方案。用户本轮分流要求优先：**真人使用照片抠图合成；非真人使用 2D 部件编辑，或 3D 捏脸／固定模型。** 本文只规划数据与制作流程，不表示编辑器、渲染器或视频通话已交付。

## 首次设定

1. 先由用户选择“真人照片／2D 角色／3D 角色”，不根据图片风格或识图描述猜测。路线与 AI 公司、模型、固定性格分别保存，外观制作不能重新绑定恋人。
2. 真人：导入原照片 → 预览主体 → 保留／擦除修整 → 用户确认人物与附属物 → 保存基准。背景混乱、多人或半透明部件均允许人工选择，不把最大物体自动认作 OC。
3. 2D：使用已有部件或导入分层素材，编辑脸、发型、衣服、翅膀、道具及位置，确认后保存可重复渲染的角色包。单张立绘需先拆层、补画和绑定参数，透明 PNG 本身不是完整 Live2D。
4. 3D：选择已支持的固定基础模型，调整脸型等已开放参数，装配衣服与附属物，确认后保存模型及参数。照片不能直接冒称已转换成可用 3D 角色。
5. 未提供照片的用户可以采用描述生成初始参考，但当前两次机会仍待接入次数记账和确认流程。生成结果确认前不成为身份基准。2D／3D 编辑器未上线时，不展示能进入却无法制作的正式选项；可在说明页展示计划。

## 外观标识与迁移

建议新增版本化 OC 档案，字段名称为方案，并非当前已有接口：

| 字段 | 作用 |
| --- | --- |
| `appearanceRoute` | `photo_subject / parts_2d / avatar_3d / unknown`，由用户明确选择 |
| `ocId`、`identityModelId` | 稳定角色身份及已确认的制作包，不能每次生图重新生成 |
| `identityRevision`、`visualVersion` | 修改制作包时建立新修订；供库存提交检查，不覆盖旧消息附件 |
| `sourceRefs`、`packageSha` | 原图／主体／模型／纹理的本地 ID、SHA 与制作包清单 |
| `parts`、`rigVersion` | 部件 ID、来源、侧别、层级／骨骼挂点、变换与可动范围 |
| `status` | `draft / awaiting_confirmation / ready / unsupported`；失败保留原稿 |

原始资源不可变，渲染实例只改变场景、姿势和相机。照片路线的 `identityModel` 是已确认主体与允许的素材集合；2D 是固定部件包及参数；3D 是固定网格、纹理、形变和骨骼。镜头不能触发换脸、换模型或丢弃道具。

旧 `VisualProfile` 只有 `mode=none/import/generate`、参考 ID 和版本，无法证明是真人还是非真人。迁移时写 `appearanceRoute=unknown`，保留 ID、SHA、版本及已有消息，不重抠、不重绘；下次使用外观能力让用户补选并确认。身份、制作包与版本更新采用一次提交；后台任务提交前校验同一 `ocId/revision/visualVersion`，旧任务只能保留为旧版候选。

## 武器、多翼及左右关系

部件是可扩展列表，允许单翼、六对翼、独立武器、尾巴、非人器官和透明光效。每个部件记录稳定 ID、用户确认的语义及角色自身的左／右／中央／未指定侧别；相机画面左右与角色左右分开处理。EXIF 校正可以修正源照片方向，自拍或换镜头不得静默镜像伤疤、翅膀与持武器手。

照片路线保留所有已确认 alpha 区域，包括断开的道具，不按人体模板裁掉多余部件。2D 保留独立层及遮挡关系；3D 扩展挂点和骨骼，基础模型缺少适配能力时明确受限，不偷偷套成人类双翼模板。识图只能给待确认建议，不能凭 caption 自动数翼、批准一致性或写成用户原话。

## 真人基准与两种备用办法

**基准：无人背景生成 → 本地合成已确认的照片主体。** 人物 RGB 来自确认主体，保留原图／主体 SHA；采用有界解码、平移与等比缩放，不重绘脸与附属物。只改变背景、版面及可解释的遮挡；主体像素的一致性不等于场景透视正确，仍需检查比例、接地和遮挡。人物重打光会改变 RGB，应作为另一种处理状态，不称像素不变。

这条路线快、能复用库存，但单张照片无法提供真实的新侧脸、背面、手部动作或第一人称肢体。没有对应素材就选择无人风景、原姿势画面或暂不发图。长发入镜、男女性别影子等必须来自该 OC 已确认部件或有依据的渲染；不能仅凭性别假定长发、身高或影子长度。

备用一：用户补充并确认多角度／姿势照片，建立同一 OC 的素材组。身份保持直接来自照片，离线选择快；代价是素材准备、光照与背景适配成本，仍无法自由生成任意姿态。

备用二：固定参考图条件重绘新姿势／镜头，结果作为待确认候选。能扩大场景，但有额外网络等待与调用成本，脸、比例、伤疤和道具可能漂移。用户批准后才能加入身份素材组与自动发图库存；失败沿用基准，不自动替换。Agnes 实测的参考重绘已出现漂移，不能以 HTTP 200 当一致性通过。

## 日轨迹到聊天图片

目标链路为：

`dayPlan → scene / camera / pose → 对应路线 render → 候选检查 → 本地库存 → 聊天附件 → 原文记忆检索`

日计划按日期和时区持久化，内容是 OC 的虚构日常，不能当成用户行踪。场景规划结合当前时段、性格、近期已发素材和可用姿态，生成场景／相机／姿势参数；人物身份不由规划器决定。2D 渲染固定部件和动作；3D 渲染固定模型与姿态；真人先选已确认姿势，再合成背景。三路共享库存与发图协议，不共享一个会随提示词变化的“人物生成器”。

后台按 `ocId/revision/dayPlanId/scene/camera/pose/renderVersion` 去重预制，人物合成素材与无人背景分别缓存；有可用库存就不在回复前台等待生图。初次缺库存时仍可先回答，生成失败保留聊天和旧资源。凌晨日期切换不删除昨天发出的照片，Android 休眠可能延迟后台任务，因此需前台日期检查与后台补偿；不能承诺系统必在 00:00 执行生成。

库存记录人物版本、场景来源、SHA、确认状态及生成来源。选图只用当前身份版本；发出的消息保存原文、作者、秒级时间、附件 ID／SHA 和当时的日轨迹引用。以后“那天你给我看的小猫”可检索消息并回取原附件，不能重新生成一张图替代旧图。视觉描述、场景安排与检索标注都是派生资料，既不融合改写原文，也不冒称用户说过。

## 分阶段交付及验收

1. 先完成当前客户端、轨迹、聊天 UI 的统一验证，再新增外观路线持久化和 `unknown` 迁移测试。验收重启不换身份、不动 Key／性格／原文；旧用户不会被自动判成真人。
2. 先交付真人基准闭环：独立凭据、背景生成、本机合成、确认与库存、两次初始机会记账。验收多翼武器不丢、左右不翻、源图 SHA 保留、并发换版本拒绝旧结果；超时状态明确且不盲目重试扣费。
3. 非真人先做小而完整的 2D 部件编辑与保存／重开／渲染，扩展附属部件及手工确认；真正 Live2D 拆层和 rig 后续独立验收。能编辑且产物能加载后才开放正式选择入口。
4. 再做固定 3D 模型的参数编辑、保存、相机与动画；验收低配置手机内存、帧率、遮挡与非对称部件保持。模型导入适配与授权另行落实，不宣称支持所有模型。
5. 三路库存稳定后接通话：同一 OC 制作包绑定实际播放嘴型／动画，可打断音频与全双工单独测。路线无法制作的姿势明确受限，优先保持角色身份连续。
