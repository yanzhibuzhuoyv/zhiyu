# 0.2.16：时间、语音、自像、重框动画与天气

基线为 e08b1b6 / 0.2.15。本轮按用户新反馈 41–46 继续修复。ADB 初始没有手机，以下自动验证与音频合成都在隔离模拟器完成，不冒称新的红米实测。原聊天、原录音、原图、绑定及逐条原文 RAG 保持。

## 41：普通聊天也必须使用当前手机时间

上一轮独立“现在几点”能本机回答，但普通对话、主动消息和带图日常依然可能由模型产生错误报时；日常分享甚至未附本轮 Runtime。现在这三个入口都取本次设备时间与时区；系统网络缓存只有与设备时钟相差不超过 120 秒才采用，避免一个相差八小时的缓存覆盖用户可见时钟。这不是把 IP 出口当作用户时区，也没有在无手机情况下断定这次红米问题一定由校时缓存造成。

对模型明确声称“现在凌晨一点/都凌晨1点了”等、且与当前小时冲突的窄域报时，由本机纠偏并保留其余正文，不再多付费调用模型。没有明确当前报时的普通数字不动；故事、其他时区、引号、代码和引用原文保留。流式回答只缓冲可能的当前报时及未完成的引用定界符，普通尾部仍及时输出；报时在句边界纠偏后才交给语音出口，保护状态跨句/换行保留。此规则不能保证任意隐含时间表达都被识别，不会为“早些休息”等每种措辞编造一个万能字符串替换器。

实际回归把时间固定为上海 09:07:09，让最终 provider 响应故意返回“现在凌晨一点了。新买的书是什么？”，验证普通聊天、日常分享、主动联系保存正确报时，并保留其他问题；没有额外模型请求。另覆盖逐字流、跨句引号与多行代码。

## 42、45：语音理解与输出

现有链路是原录音 → 本机 ASR → 模型接收转写，模型没有收到音频。本轮把实际输入来源作为可信状态传入：当前已验证录音或通话转写才标 ASR，普通文字不会因为提到“错别字/语音”就被误标。模型应结合当前语境理解高置信谐音，自然回答，不把错字引成新话题；专名、数字、日期、否定、意愿和承诺不能擅改，不确定时只确认必要含义。原转写、音频与 SHA 原样保存；不能声称模型听出了未上传的音色或背景声音。

语音合成原本只调全段基准音高、插标点停顿。现加确定性的轻微句末语调和力度包络；保持帧数和首尾采样位置，保留用户选择的基准音色及音高设置，无随机噪声、无新模型或网络依赖。真实内置模型分别合成三个问句/陈述的前后 WAV，经实际引擎出口比对 1/1 通过、1.98 秒，六个文件 SHA 已校验：

- 问句：[调整前](../artifacts/feedback4146-voice-samples/speaker-0-0-before.wav) / [调整后](../artifacts/feedback4146-voice-samples/speaker-0-0-after.wav)
- 陈述：[调整前](../artifacts/feedback4146-voice-samples/speaker-0-1-before.wav) / [调整后](../artifacts/feedback4146-voice-samples/speaker-0-1-after.wav)

这是有限改善，不是更换成真人情感语音；没有用自动测试宣称主观听感已达标。ASR 来源和理解规则验证也不等于真实环境识别准确率提升。详见 [语音专项](VOICE_INPUT_AND_CADENCE_2026-10-19.md)。

## 43：固定自像的归属

现在区分原文件相同、完整解码像素相同、用户明确确认这三类依据；“先发图、下一句说这是你”可持久绑定到当前 OC 的图片归属。问句、否定、转述不算确认，OC 改变后不继承旧确认。归属元数据有界，不改 OCR、图片、原话或旧模型猜名。

已确认自像的整句纯识别问题可以直接自然回答“是我呀”等，不再让模型猜出的其他角色名推翻已确认归属；同时问其他事情仍保留模型回答路径。完整像素路线只认严格全图相同，不使用人脸相似度或抽样冒认；JPEG 重压、裁剪、不同姿态仍需真实视觉对照，不能保证任意变体都准确。详见 [自像专项](OC_SELF_IDENTITY_2026-10-19.md)。

## 44：重新框选后仍能活动

用户确认故障为“画面正常，但人物不动”。旧默认框只在包围矩形中心产生动作，手动凹形框/擦除后，中心可能已是透明区；真实 GPU 回归修前变化像素为 0。重建的头部还可能因 ID 不叫 auto_face 而走另一套全局动作，强度设为 0 仍有 headX。

现在按当前头部实际保留像素和笔迹重建局部场，按 face 部位类型工作；33×33 网格内只移动轮廓内部，孔洞、背景和边界固定，眼口继承相应头部动作，强度 0 和全擦除保持静止。已验证手绘凹形 → 预览 → 保存读取 → GPU 像素，以及重新打开后的强度。旧包不静默重写，需要用户在新版重新预览并“保存并用于通话”。[手机教程](LIVE2D_PHONE_GUIDE_ZH.md)

## 46：天气持续刷新与真实状态

旧天气只在恢复页面时刷新，连续使用可能过期；刚进入页面立即问天气时，定位尚未完成也会得到空上下文。现在前台每分钟检查一次到期，天气仍按 15 分钟间隔刷新。用户明确询问天气且缓存缺失/到期时，在已开启、已授权、仍在前台的条件下尝试一次有界刷新；普通文字不触发额外定位，后台不强行获取前台定位。

模型获得 ready、stale、awaiting_fix、permission_missing、disabled 等实际状态；只附有效天气，不捏造雨量和温度，不把等待定位说成永久不支持天气。关闭、撤权、定位失败或网络失败不会假装已经看到天气。坐标只在请求时粗略化，不写入存储，不发给聊天公司；天气字段和单位按现有 [Open-Meteo 官方接口](https://open-meteo.com/en/docs) 处理，当前定位使用 [Android LocationManager](https://developer.android.com/reference/android/location/LocationManager) 的前台接口。本轮没有读取用户真实位置。

审查另外复现并修复跨入口冲突：天气发布和关闭共享原子保存边界，迟到结果不能重新开启开关；普通刷新不把旧内存天气写回，不覆盖聊天入口刚取得的新缓存。权限、关闭、取消、失败、更新顺序及新旧缓存回归均通过。

另用固定公开北京坐标请求 App 相同 URL 做电脑 HTTPS 冒烟，`feedback4146-weather-public-http-smoke-r1.json`：200、501 bytes、1.934 秒，单位符合解析协议，观测时间距请求约 287 秒，位于现有有效期内。没有使用用户位置或 AI Key，也不以电脑 HTTP 结果冒充 Android 定位或红米网络验收。
