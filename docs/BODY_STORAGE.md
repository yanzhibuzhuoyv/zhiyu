# 正文无损存储与兼容迁移

2026-10-06。后端新写入可以逐条压缩正文，API继续返回相同原文、作者、消息ID、保存时间和来源。旧TEXT与新BLOB可以混存，不融合、不摘要、不过滤原话。Android无需处理压缩格式。

## 正式格式与读取

`body_codec.py`使用`ZYBC1\0`版本头、4字节原UTF-8长度、32字节SHA-256与zlib level6，头部共42字节。原文达到1024 UTF-8字节且连头至少节省10%才使用BLOB，否则仍是TEXT。保存与FTS建立在同一事务内，索引使用原文，不索引压缩字节。

解码验证版本、声明长度、有限展开、单一流结束/尾随数据、SHA及严格UTF-8。研究/兼容读取上限16MiB，不改变API的用户16000字符或厂商回复限制。旧TEXT没有存储校验和，只检查类型/编码/长度，不宣称能检测其中任意等长篡改。校验和用于发现损坏，不能替代身份验证或防止有写权限者重算校验和。

历史API解码后返回原消息；近期预算和原文片段使用Unicode字符长度及偏移，不使用BLOB字节长度。RAG/近期/回填先查询有界ID和偏移元数据，再逐条读正文，避免把整批长原文搬入SQL排序临时文件。多语句读取使用同一SQLite读快照。`/messages`全历史和`/history`每页最多100条仍有返回全文的体积成本，不称为所有读取恒定内存。

存储损坏返回安全503，不向客户端暴露原文、编码包或内部异常。保存工作移入线程池，仍受当前会话锁保护。正文压缩不改变provider/model绑定、preset/custom人格、单页连续聊天或文档RAG开关。

## 旧正文迁移

`ChatDatabase.migrate_bodies(owner,id,after=0,through=None,batch_rows=128,byte_limit=8MiB)`是内部维护接口，本轮没有添加远程迁移端点，也不在启动时自动改写所有旧正文。

每次只处理一个owner校验后的会话、一个`BEGIN IMMEDIATE`原子批：最多128目标行，先读序号和原UTF-8大小，再逐条编码。预算保守预估原+新载荷；单条超预算时只处理该条，并显式标记`oversized_row`，8MiB不是WAL或临时文件的绝对上限。库仍持写锁，不能据health响应声称并发写不受影响。

第一批返回固定`through`快照边界，后续传回这个值和最后实际处理的`after`。无收益的TEXT也推进游标，后来的消息不进入同一次迁移。任何编码、SQL或提交错误均回滚整个当前批；以前成功提交的批保留，因此整个任务的回滚依赖完整备份。迁移只更新content，不改ID、角色、时间、来源、原文片段或FTS。

**降级不能只换回旧镜像**：旧程序不认识正文BLOB。先停止写入，保留完整备份和身份文件，在副本验证恢复，再恢复兼容旧版本的TEXT数据库。新程序能读旧TEXT，不等于旧程序能读新BLOB。不要在聊天中自动VACUUM。

## 三层策略范围

`memory_lifecycle.py`提供中期/长期/永久的可测试纯策略，输入必须是已经验证并隔离的原文区间标注；它不从自由文本自动判断用户生日或爱好，也不写数据库、移出索引或改生产排名。跨天独立证据、原文作者/主体、肯否/转述、有效状态和未解决承诺分别判断。明确独立事件来源可支持不同天重复同一句愿望；缺来源证明时保守去重。实验的3次/6经过天及最多15%乘数不是已确认最优。

自动识别、持久标注、主动冷索引和冷回查尚未启用；当前每条成功保存的消息仍有活跃FTS入口。实现这些功能前必须验证最新更正优先、主体误归属和重启不回灌，见[三层方案](MEMORY_LIFECYCLE.md)。
