# 温柔相伴预设：预注册验收协议 v1

本轮目标是让用户能够试用一份固定的恋人预设 `warm_v1`。比较已有 `gentle` 与新预设的自然回答，不把结构化引文模式切入聊天。题库是独立 Agent 在看模型输出前编写的全新合成材料，路径为 `scripts/companion_preset_cases.json`，版本 `companion-preset-independent-v1`。不读取私人聊天、原始 RAG 或用户个人信息。每条来源保留自己的作者、时间与原文，不合并改写。

题库共 20 题：日常分享 5、明确记忆 6、不确定证据 4、人格与互动边界 5。每题最多 6 条独立原文和 2 条近期消息。本版实际最多 3 条来源、2 条近期消息。当前时间统一 `2026-10-07T12:00:00+08:00`，来源时间均早于此时。金标 `expected`、类别说明和审核意见不进入模型提示词。

固定事实覆盖：用户生日与助手猜测分离；最新居住决定覆盖旧犹豫；助手尚未到期的聊天承诺不能算已履行；多条同日原文共同回答购买变更；相近名字与不同作者不能混淆；临时饮食限制不能永久化。缺席证据覆盖：不确定旅馆名字、同事事实和用户假设、片名及朋友经历的词汇相似噪声、未定日期的看海计划。互动覆盖：日常无需硬提旧事、停止连环追问、现实亲友交往、真实身份能力、固定温柔性格、明确拒绝旧事、用户主动要求长回复。

计划调用为 `20 题 × 2 预设 × 2 思考模式 = 80 条`。每条仅调用一次，不挑选最好回答、不自动审核改写、不重试修饰失败。两预设在同一题、同一模式使用完全相同的问题、近期原话、来源、时钟、角色和称呼配置，只有预设文字不同。按题交错两预设先后，思考开关分别统计；结果不回写其他试验历史。开启思考和关闭思考的自然度差异不能当成检索顺序差异。本轮材料检索输入固定，并不研究 A/B 检索顺序的优劣。

正式调用前冻结题库、协议、运行脚本、预设文字、提示构造代码、模型 ID、最大输出参数、源文件哈希及日程。如需修改预设或材料，保存新版本和差异，另起一轮，不覆盖本轮失败。生产请求的超时策略与实验无读取截止必须分别报告。实验沿用已授权的高输出额度并等到完整答案，不人为缩成短回复；只有 `persona_user_requests_long_reply` 含用户主动提出的至少一千汉字要求。该题记录实际汉字数；模型以 `stop` 主动结束且不足要求属于回答意愿未满足，不算传输截断。

机器检查只负责请求状态、完整 SSE、`[DONE]`、结束原因、非空内容、首个用户可见正文时间、完整正文等待、正文长度和 token 使用。思考内容只记录长度和时序，不保存或展示其正文；API Key 不进入输出。HTTP 成功、格式合法、关键词命中和长度达标均不能证明回答语义正确。

独立复查者阅读每一条完整最终答案及该题全部原文，逐项判断 `expected`，并记录准确摘录与理由。分开记主问题满足、作者归属、日期及临时/当前范围、查不到与从未说过的区分、无据现实经历、假设与事实区分、人格稳定、是否强制翻旧账、重复安慰和多余追问。自然度使用 1–5 分：1 为明显僵硬、反复核查或不合互动意愿；3 为可用但有套话、冗长或生硬；5 为具体贴合当下、亲近连贯且没有多余流程。不能因为出现昵称、撒娇词或某句模板就判高分。

输出缺席、传输失败、事实错误、语气质量和长回复不足分别统计，失败保留在分母。每臂只有一次采样，报告本轮题目通过数与观察，不报告 `pass@3`、长期稳定率或总体可靠保证。独立 AI 复查属于语义评阅，并非人工盲审；评阅者不知道金标之外的真实私人生活。两臂同一来源下的随机差异不能证明整体检索改进。

试用前还需确认：新预设可以正常选择、绑定后不能改动完整预设、已绑定的旧预设文字没有被静默替换；原文与 API Key 的存储边界通过应用测试。若出现无据旧事、查不到即否认历史、性格漂移或等待显著增加，明确记录限制，保留旧选项并将新版本标为试用，不将一轮样本包装成已解决全部记忆问题。
