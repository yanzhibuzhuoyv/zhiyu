# 双方长字段 Docker 冒烟

万轮报告里的普通用户消息中位数332字符，AI演示回复最多255字符；38条接近16k的长用户消息并不等于双方持续输出长文本。此前的40.46MiB只能描述该万轮负载，不能据此估计长回复聊天。

2026-10-05 17:12（北京时间）补测通过。使用万轮测试同一个运行镜像，注入仅在测试脚本内的确定性回复器；真实启动Uvicorn并经loopback HTTP登录、发送、分页、重启恢复及删除。没有用TestClient或批量SQL代替聊天请求，也没有调用云厂商。生产应用代码、8791服务和现有数据卷没有改动。

## 字段和检查

- 36条用户消息各精确16,000字符；32条AI回复各16,000字符，另4条各64,000字符。字符数按Python/SQLite Unicode码点统计，不等于UTF-8字节或模型token。
- 内容为不同的随机中文字符、随机字母数字串、表情和换行，固定seed可复现；不是只重复一个短句。64k回复是合成存储边界，不是云模型生成能力或当前max_tokens配置的实测。
- 再发送25个短轮次，把这些长记录移出最近20轮上下文；6项检索分别核对16k用户、16k AI和64k AI原文的中部与尾部。必须匹配原ID、role、turn_id、保存时间及原文子串；缺失、改写或作者错误均失败。
- 共67完整轮/134条消息，重启前后各2页，逐条SHA256包含ID、角色、正文、来源和时间；旧token真实401，同Key重新登录恢复全部原文。
- 16,000字符真实HTTP接受，16,001字符真实422，并核对消息、正文字节、片段与FTS计数无变化。
- 134条消息/2,162个片段逐个核对偏移连续覆盖首尾、单片段不超768字符，以及对应FTS行存在；其中72条长消息。所有SQLite quick_check=ok。
- 78次HTTP请求，0意外失败，无自动重试；清理自己的临时会话后消息、片段、FTS计数恢复0。测试工具Windows和无网络Linux容器均46项回归通过（原压力工具30项＋长字段16项），ruff通过。
