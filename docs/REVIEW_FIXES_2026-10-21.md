# 知语 0.2.20 · 审查问题修复

本轮处理 [整体审查](CODE_REVIEW_2026-10-21.md) 的 R1–R6，版本 `0.2.20 / code 26`。范围是原文保留、待发消息恢复、生活照交付及探针测试。旧版本已丢失且没有副本的原文无法由本次升级补回。

## 改动

| 问题 | 原行为 | 修复后的行为 |
| --- | --- | --- |
| R1 原文误删 | 第一分块向量相似便可能删除整条消息 | SHA 缩小候选，再比较经过校验解压的完整原文；必须同作者角色、同消息来源且存在更新副本。删除事务重新检查副本和保护条件，部分匹配不删除 |
| R2 待发消息丢失 | 已清空输入框的待发队列仅在 ViewModel 中 | 清空前写入本机 SQLite 发件箱；重建恢复原话、顺序、图片和语音引用。未提交项由用户重试，已提交但回复未知的项不再次请求模型，已完成批次自动清理残留 |
| R3 保存失败耗掉生活照 | 标记照片已用后再保存消息 | 使用同一聊天数据库连接和事务保存消息、记录照片交付；失败同时回滚，两个选择器并发提交只能交付一次 |
| R4 扫描停滞 | 每次只检查最早 400 条 | 持久记录扫描位置，逐批推进，到尾部后回绕；不靠修改时间跳过原话 |
| R5 生活照永久封顶 | 已发 SHA 达到 4096 个便拒绝任何新图 | 迁移到 SQLite 去重账本，只查询当前候选的 SHA；不再设整个对话的 4096 张寿命上限，保留旧去重凭据 |
| R6 探针接口失配 | 三个测试仍按旧位置参数调用 | 明确传递普通、50M 和续跑参数，覆盖各模式及停止回调；实际测试全部截断外部调用 |

另外修复了本轮回归发现的三个边界：

- 连续发送的后一条正在落盘时，队列不会提前发送或展示前一轮回复；用户期间继续编辑的文字保留。
- 删除待发项尚未完成时，重试和队列发送不能抢走该项。
- “最近 100 条”按当前对话内的实际条数保护，不再拿全库自增序号减 100；其他会话插入造成的序号间隔不影响保护。

## 数据与兼容性

聊天库 schema 从 3 升至 4，兼容 1–3 的升级入口，新增精确重复索引、照片交付账本和有界发件箱；不清空聊天、绑定或 Key。发件箱限制 32 条、每条最多 16000 字符，原文压缩并校验 SHA，不复制 API Key。照片和语音在待发期间加入清理保护，显式放弃后才解除。

迁移旧照片记录时，记录与迁移标志同事务提交；旧 SharedPreferences 不擦除。去重账本仅保存 SHA 和对话标识，取消寿命上限后仍会随交付数量增长。

原文裁剪仍沿用年龄、长期/永久/手动标记、附件、请求来源、最近消息和 2.5% 数量上限等保护条件。此次没有改动语义召回的打分方式，也没有用“摘要融合”替代原话。精确重复去重会保留较新的完整副本，不能将它描述为每个重复发生时间都永久保留。

发件箱修复接入当前手机独立版本的 `LocalChatRepository`；历史网络后端没有新增发件箱。生活照事务修复针对 R3 的显式生活照交付路径，不声称已经把自拍库存和提前借图的其他独立账本也改成同一事务。
